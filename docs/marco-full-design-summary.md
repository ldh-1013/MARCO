# 마르코! (MARCO!) — 게임 기획 최종본

> 4인(술래 1 + 러너 3) 기준 정식 밸런스 사양.
> 문서 끝에 **최종 검수 결과**와 이번에 수정한 문제 목록이 있다.

## 1. 한 줄 정의

> **말해야 앞이 보이는데, 말하면 술래가 듣는다.**

**핵심 게임 루프 (변경 금지)**

```
완전한 암전 → 소리 발생 → SoundPulse → 제한적인 시야 확보 → 위치 노출 → 추적/회피
```

### 2.1 인원 확장 기준

**현재 버전의 모든 밸런스 수치와 승리조건은 3 Runner 기준으로 잠근다.**

| 구분 | 상태 |
|---|---|
| 4인 (러너 3) | **정식 밸런스 사양.** 모든 수치가 이 기준으로 확정됨 |
| 5~6인 (러너 4~5) | **확정 밸런스 아님.** 향후 확장 가능 구조로만 열어둔다 |

러너가 4~5명이 되면 승리 목표 인원(현재 "탈출 2명")을 별도로 재계산해야 한다.
이 계산은 현재 버전에서 확정하지 않는다.

### 2.2 4인 기준에서만 성립하는 구조적 사실 [수정]

**태그 2명 도달 시 라운드가 즉시 종료**되므로(§8.3), 3 Runner 기준에서는
**플레이 중 동시에 존재하는 메아리가 최대 1명**이다.

| 태그 인원 | 메아리 수 | 상태 |
|---|---|---|
| 0명 | 0 | 진행 중 |
| 1명 | **1** | 진행 중 |
| 2명 | — | **라운드 즉시 종료** |

따라서 다음 서술은 **5~6인 확장 시에만 의미를 갖는다.**

- 메아리끼리 서로 보임 (§6.2)
- 메아리끼리 자유 음성 대화 (§5.4)
- "메아리가 늘어 정보가 혼탁해진다" (§14.1)

**4인 기준 라운드 전체의 노크 최대 발생량은 5회다** (메아리 1명 × 5회).
이 사실은 §16-G 가짜 소리 검증의 전제가 된다.

## 3. 역할 시스템

### 3.1 세 가지 역할

| 역할 | 인원 | 등장 시점 | 목표 |
|---|---|---|---|
| 🏃 **러너** | 3명 | 라운드 시작부터 | 밸브 3개를 열고 탈출 |
| 👁 **술래** | 1명 | 라운드 시작부터 | 러너를 잡거나 시간 초과로 승리 |
| 👻 **메아리** | 최대 1명 (§2.2) | 러너가 태그당하면 전환 | 노크로 계속 게임에 참여 |

### 3.2 역할 전환 구조

```
게임 시작
   ├─ 술래 1명 배정 (OwnerId 기준 첫 번째 = 호스트)
   └─ 러너 3명 배정
             │
             │ 술래에게 태그당하면 (반경 1.2m 접촉 즉시)
             ▼
          메아리 (역방향 없음. 라운드 종료까지 유지)
             │
             ▼
         결과 화면
```

### 3.3 역할별 능력 수치

| 수치 | 술래 | 러너 | 메아리 |
|---|---|---|---|
| 기본 이동속도 | 5.0 × 1.08 = **5.4 m/s** | **5.0 m/s** | **6.0 m/s** (유령 비행) |
| 질주 속도 | 없음 (상시 5.4) | **7.5 m/s** | 없음 |
| 질주 스태미나 | — | **5초 (소진 시 3초간 -20%)** | — |
| 청취 배율 | **반경 ×1.2 / 지속 ×1.5** | ×1.0 | 거리·차폐 무시 (§3.6) |
| 방향 표시 | **있음** (§5.1 대상 소리만) | 없음 | 없음 |
| 태그 | 태그함 (반경 1.2m) | 태그당함 | 태그 불가 |
| 충돌 | 벽 충돌 있음 | 벽 충돌 있음 | **없음** (벽 통과) |
| 발소리 | 항상 질주급 6m (5.4 > 5.0 기준) | 걷기 2m / 질주 6m | **없음** |

### 3.4 술래 전용 — 외침

술래가 외침을 사용하면 **22m 안의 살아있는 러너가 자동으로 짧은 비명을 낸다.**
플레이어가 직접 "폴로"라고 말하지 않는다. 캐릭터 SFX로 자동 발생한다.

**발동**

| 항목 | 값 |
|---|---|
| 선딜레이 | **1초 정지** (선딜레이 중 이동하면 취소, 쿨다운 소모 없음) |
| 쿨다운 | **45초** (선딜레이 완료 시점부터 계산) |
| 술래가 발생시키는 소리 | **고함 등급 SoundPulse** (§5.1) — 발생 반경 22m |

### 3.4-A 외침의 세 가지 "22m"를 분리한다 [수정]

외침 하나에 22m라는 숫자가 여러 번 등장하지만 **서로 다른 세 개념**이다.
구현 시 절대 같은 것으로 취급하지 않는다.

| # | 개념 | 값 | 성격 | 차폐 적용 |
|---|---|---|---|---|
| **A** | **외침 SoundPulse 발생 반경** | **22m** | 술래가 만드는 **소리 이벤트**. 고함 등급 | **적용** |
| **B** | **공포 반경** | **22m** | 러너의 자동 비명을 트리거하는 **능력 효과 범위**. 소리가 아니다 | **미적용**(순수 직선거리) |
| **C** | **비명 청취 반경** | **10.8m** | 술래가 그 비명을 인지하는 범위 = 9m × 1.2 | **적용** |

> **A와 B가 우연히 같은 22m일 뿐 서로 다른 판정이다.**
> A는 소리이므로 벽을 지나면 감쇠하지만, B는 능력 판정이라 벽 뒤 러너도 놀란다.
> 벽 뒤 러너는 비명을 지르지만 그 비명은 차폐로 감쇠되어 술래에게 닿지 않는다.

### 3.4-B 외침 1회에 누가 무엇을 얻는가 [수정]

**① 술래 자신**

| 얻는 것 | 내용 |
|---|---|
| 시야 | 자기 외침 파문(발생 22m)으로 **주변 지형 22m를 본다** |
| 정보 | 청취 반경 10.8m 안의 비명만 인지 (방향 표시 포함) |

**② 다른 플레이어가 술래의 외침을 인지하는 범위**

이것은 **일반 SoundPulse 청취 규칙을 그대로 따른다.** 별도 규칙이 아니다.

| 청취자 | 계산 | 결과 |
|---|---|---|
| 러너 | 22m × 1.0 (러너 청취 배율) | **22m** |
| 메아리 | 거리·차폐 무시 (§3.6) | **전역** |

> **주의**: §5.1의 "고함 술래 청취 반경 26.4m"는 **다른 사람이 고함쳤을 때
> 술래가 듣는 범위**다. 술래 자신의 외침에는 적용되지 않는다.
> 술래가 외침으로 자기 위치를 노출하는 범위는 **러너 기준 22m**이다.

**③ 22m 안의 러너 — 거리별 반응**

| 거리 | Runner 반응 | Seeker가 비명 인지 |
|---|---|---|
| **0 ~ 10.8m** | 비명 | **인지** |
| **10.8 ~ 22m** | 비명 | **인지 못함** |
| **22m 초과** | 비명 없음 | 인지 불가 |

10.8~22m 구간의 러너는 자기가 비명 지른 것을 알기에 "들켰다"고 믿지만
실제로는 술래에게 아무 정보도 가지 않는다. **이 정보 비대칭이 공포의 핵심이다.**

**비명 억제 — 숨 참기**

| 대응 | 비용 | 결과 |
|---|---|---|
| 숨 참기 (선딜레이 1초 안에 입력) | 숨 게이지 **3초** | 비명 발생 안 함 |
| 잠수 중 | 이미 게이지 소모 중 | 자동 억제 (물속이라 비명 못 지름) |
| 게이지 3초 미만 | — | **억제 불가.** 비명 강제 발생 |
| 22m 밖 | 없음 | 반응 자체가 없음 |
| 아무것도 안 함 | 없음 | 비명 발생 (9m / 1.0초) |

### 3.4-1 숨 게이지 — 통합 상태 전이 규칙 [수정]

**게이지는 하나뿐이다. 새 게이지를 추가하지 않는다.**
잠수와 비명 억제가 **같은 게이지 하나**를 공유한다.

**상태 정의 (4개, 상호 배타적)**

| 상태 | 판정 기준 |
|---|---|
| **잠수** | 카메라(머리)가 수면 아래 |
| **수면** | 몸이 물 안에 있고 머리가 수면 위 |
| **물 밖** | 콜라이더가 물 볼륨과 완전히 분리 |
| **회복 대기** | 위 3상태와 별개로, **마지막 소모 시점부터 2초간** 유지되는 플래그 |

**소모**

| 원인 | 양 |
|---|---|
| 잠수 유지 | **초당 -1** (연속) |
| 비명 억제 | **-3** (즉시, 1회성) |

**회복 (단일 규칙)**

```
회복 조건: 상태 ≠ 잠수  AND  회복 대기 플래그 = false (마지막 소모 후 2초 경과)

회복 속도:
  상태 = 수면   → 초당 +2
  상태 = 물 밖  → 초당 +4
```

**최대 8초에서 상한.** 회복 중 다시 잠수하면 즉시 회복이 중단되고
초당 -1 소모로 전환된다(회복 대기 플래그도 다시 2초로 리셋).

**상태별 소요 시간 (계산 검증)**

| 상황 | 소모 | 대기 | 회복 | 총 |
|---|---|---|---|---|
| 육상 비명 억제 1회 | -3 | 2초 | 0.75초 | **2.75초** |
| 수면에서 비명 억제 1회 | -3 | 2초 | 1.5초 | **3.5초** |
| 7초 잠수 후 물 밖 | -7 | 2초 | 1.75초 | **3.75초** |
| 전체 고갈(8초) 후 물 밖 | -8 | 2초 | 2.0초 | **4.0초** |

> **삭제된 규칙**: 기존 "물 밖으로 완전히 이탈하면 **즉시 100% 회복**"은
> 삭제한다. 이 규칙은 두 가지 악용을 만들었다 —
> ① 육상에서는 비명 억제 비용이 0이 되어 게이지 제약이 사라지고,
> ② 잠수 → 물 밖 → 재잠수 반복으로 게이지가 사실상 무제한이 된다.
> **물 밖 초당 +4** 가 그 의도(물 밖에서는 빠르게 회복)를 유지하면서
> 두 악용을 모두 차단한다.

**고갈 시**: 잠수 중 게이지가 0이 되면 **질식 페널티** —
강제 부상 + 이동속도 -20% 3초 + 고함급(발생 반경 22m) 파문 1회 강제 발생.

**비명 억제 직후 회복**: 가능하다. 억제는 1회성 소모이므로 2초 뒤부터
해당 상태의 회복 속도가 적용된다.

### 3.4-2 "연속 억제 2회"의 실제 의미 [수정]

게이지 8초 ÷ 억제 3초 = **이론상 연속 2회**다.
그러나 외침 쿨다운이 45초이므로, **외침만으로는 이 한계가 발동하지 않는다** —
45초면 어떤 상태에서든 게이지가 만충되기 때문이다.

**이 제약이 실제로 작동하는 경우는 잠수와 겹칠 때뿐이다.**

| 상황 | 결과 |
|---|---|
| 육상에서 외침을 45초마다 맞음 | 항상 억제 가능. 제약 없음 |
| 5초 잠수(-5, 잔여 3) 직후 외침 | 억제 가능하나 게이지 0 |
| 6초 잠수(-6, 잔여 2) 직후 외침 | **억제 불가 → 비명 강제 발생** |
| 밸브 B 수행 직후(잔여 4) 외침 | 억제 가능, 잔여 1 |

따라서 이 시스템의 진짜 긴장은 **"물에 들어갈 것인가"와 "외침을 견딜 것인가"가
같은 자원을 두고 경쟁하는 것**이다.

### 3.4-3 장시간 정지 시 자동 소리 (캠핑 방지)

목적은 숨는 플레이 제거가 아니라 **무기한 정지만 막는 것**이다.

| 항목 | 값 | 테스트 범위 |
|---|---|---|
| 발동 조건 | **20초 동안 누적 이동거리 3m 미만** | 15~25초 / 2~4m |
| 1단계 | 호흡음 — 발생 반경 **3m / 0.6초** | 2~4m |
| 증폭 | **15초마다 발생 반경 +2m** | 12~20초 |
| 최대 | **9m** | 8~12m |
| 초기화 | **5m 이상 이동 시 즉시** | 4~7m |
| SFX | 호흡 → 떨림 → 기침 | — |
| 적용 | **러너 + 술래** | 고정 |
| 미적용 | 메아리 | 고정 |

**발동하지 않는 상태 (구현 명세)**

타이머가 **정지(일시중단)**하며 파문이 발생하지 않는다. 초기화가 아니라 정지다.

| 상태 | 사유 |
|---|---|
| 밸브 상호작용 중 | 정지가 강제되는 행동. 이미 12m 파문을 내고 있다 |
| 잠수 중 | 물속 기침은 부자연스럽고, 이미 숨 게이지 압박을 받는다 |
| 설정 화면(F1) 등 메뉴 개방 중 | 플레이어가 조작 불가 |
| 낙하 복구 · 리스폰 등 이동 불가 연출 중 | 플레이어 의도와 무관 |

**미세 이동 악용 방지**: 판정은 순간 속도가 아니라 **20초 슬라이딩 윈도우의
누적 이동거리**다. 제자리 흔들기로는 3m를 채울 수 없어 타이머가 초기화되지 않는다.

**술래 캠핑 억제의 실제 작동 (계산 검증) [수정]**

이전 판은 "50초 이상 정지하면 순찰보다 시끄러워진다"고 서술했으나,
이는 **1회 파문의 반경만 비교한 오류**였다. 술래는 이동 중 6m마다 발소리를
**반복** 발생시키므로, 반드시 **시간당 누적 소음량**으로 비교해야 한다.

**① 시간당 누적 소음량 — 교차점은 존재하지 않는다**

`1회 소음량 = 발생 반경 × 지속시간` (§5.1-1) 기준.

| 구분 | 1회 소음량 | 발생 간격 | **시간당 누적 소음량** |
|---|---|---|---|
| **술래 순찰** (6m·0.8초) | 6 × 0.8 = **4.8** | 6m ÷ 5.4m/s = **1.11초** | **4.32 /초** |
| 캠핑 20초 (3m·0.6초) | 1.8 | 15초 | 0.12 /초 (순찰의 2.8%) |
| 캠핑 35초 (5m·0.6초) | 3.0 | 15초 | 0.20 /초 (4.6%) |
| 캠핑 50초 (7m·0.6초) | 4.2 | 15초 | 0.28 /초 (6.5%) |
| **캠핑 65초 이상 (9m·0.6초, 최대)** | 5.4 | 15초 | **0.36 /초 (8.3%)** |

**순찰이 최대 단계 캠핑보다도 12배 큰 누적 노출을 발생시킨다.**
120초 누적으로 보면 순찰 518.4 vs 캠핑 30.6으로 **16.9배** 차이다.

> **결론: 누적 소음량 기준으로 캠핑이 순찰보다 시끄러워지는 시점은 존재하지 않는다.**
> 호흡음은 15초에 1회뿐이라 총량으로는 순찰을 결코 따라잡지 못한다.

**② 그렇다면 캠핑 방지는 무엇을 하는가 — 탐지 거리와 좌표 고정**

이 시스템의 효과는 "총량을 늘리는 것"이 아니라 **완전 무음을 없애고,
같은 좌표를 넓은 반경으로 주기적으로 노출시키는 것**이다.

| 상태 | 발생 반경 | 술래 탐지 거리 (×1.2) | 발생 빈도 | 위치 |
|---|---|---|---|---|
| 걷는 러너 | 2m | **2.4m** | 2m 이동마다 (0.4초) | 계속 이동 |
| 캠핑 1단계 (20초) | 3m | **3.6m** | 15초마다 | **고정** |
| **캠핑 최대 (65초~)** | **9m** | **10.8m** | 15초마다 | **고정** |

- **탐지 거리가 걷기의 4.5배**(2.4m → 10.8m)로 커진다
- 그리고 그 파문이 **매번 같은 좌표**에서 나오므로, 한 번 들킨 위치는
  술래가 다시 찾아올 수 있다. 이동하는 러너의 파문은 매번 위치가 달라진다

**정확한 표현**
> **정지 상태는 누적 소음 총량으로는 순찰보다 조용하지만, 65초 이후에는
> 탐지 거리가 10.8m까지 넓어지고 그 좌표가 고정되므로 발각 확률이 급격히 높아진다.**

20~35초의 짧은 매복은 탐지 거리가 3.6~6.0m에 그쳐 여전히 유효하며,
이는 의도된 여지다.

### 3.5 메아리 전용 — 노크 (Knock)

| 항목 | 값 |
|---|---|
| 발생 위치 | **메아리의 현재 위치** (지점 클릭 방식 금지) |
| 발생 반경 | **9m** |
| 지속시간 | **1.2초** |
| 소리 등급 | **대화와 완전히 동일** |
| 쿨다운 | **25초** |
| 라운드당 총 사용량 | **정확히 5회 (재충전 없음)** |
| 사용 잠금 | 메아리 전환 후 **20초간 사용 불가** |

노크는 쿨다운마다 누르는 방해 버튼이 아니라, 5번의 기회를 언제 쓸지 판단하는 도구다.

### 3.6 메아리의 시야 — 소나

**미니맵 시스템은 존재하지 않는다.**

| 항목 | 내용 |
|---|---|
| 지형 | **끝까지 보이지 않음** |
| 파문 관측 | **맵 전체의 SoundPulse를 거리·차폐에 관계없이 관측** |
| 표현 | **단색 저채도 윤곽** |
| 발생자 식별 | **불가능** |
| 미니맵 / 생존자 위치 표시 | **없음** |
| 태그 직후 | **3초 암전 + 조작 불가** |

**정보량 제한 [수정]**

새로운 UI를 추가하지 않고 기존 SoundPulse 지속시간·렌더링 규칙으로 제한한다.

| 항목 | 초기 밸런스값 | 테스트 범위 |
|---|---|---|
| 파문 표시 시간 | 본래 지속시간 그대로 (0.4~2.5초) | 고정 |
| 잔류 흔적 | **소멸 후 3초간 감쇠** | 2~5초 |
| 동시 표시 상한 | **최근 8개** | 6~12개 |

> **8개의 근거**: 이 값은 **초기 밸런스값이며, 동시 소리 발생 주체 수와는
> 무관하다.** 목표는 메아리가 **최근 전황은 읽되 장시간 누적 정보를 축적하지
> 못하게** 하는 것이다. 상한을 두는 이유는 파문이 화면에 무한히 쌓이면
> 메아리가 사실상 "소리로 그린 지도"를 갖게 되기 때문이다.

**플레이테스트 판단 기준**

| 관찰 | 조치 |
|---|---|
| 메아리가 화면만 보고 러너 동선을 예측한다 | 6개로 축소 |
| 메아리가 "방금 어디서 소리 났는지" 놓친다 | 10~12개로 확대 |
| 화면이 파문으로 가득 차 개별 파문 구분이 안 된다 | 축소 + 잔류 2초 |
| 메아리가 노크 위치를 못 정한다 | 잔류 5초로 확대 |

**금지**: 지형 표시, 발생자 식별, 러너 위치 자동 추적, 미니맵.

### 3.7 메아리의 방향 감각

메아리는 지형을 볼 수 없고 노크가 현재 위치에서 발생하므로 최소한의 방향 감각이 필요하다.
**미니맵·지도·러너 위치 표시·전체 맵 HUD는 추가하지 않는다.**

| 수단 | 내용 |
|---|---|
| **8방위 나침반** | 화면 가장자리에 아주 흐린 8방위. **바라보는 방향만** 알려주며 위치·지형은 알려주지 않는다 |
| **자기 실루엣 발광** | 메아리 본인의 몸이 약하게 발광해 자기 이동을 체감 (§6.1 림라이트 재사용) |

나머지 공간 파악은 관측되는 파문의 위치 관계로 스스로 추론한다.

## 4. 시야 시스템

### 4.1 핵심 규칙

**화면의 기본값은 완전 암전이다.** 상시 시야는 술래도 러너도 0%다.

### 4.2 파문이 보이는 두 단계

| 단계 | 조건 | 실패 시 |
|---|---|---|
| **1. 청취 판정** | 청취 반경(§5.0) 안인가 | 아무 정보 없음 |
| **2. 렌더 판정** | 청취 통과 + 카메라에서 그 지점이 실제로 보임 | "들렸다는 느낌"만, 링 없음 |

**청취와 렌더는 항상 분리해 구현한다.** 청취 반경 안이어도 시야가 막히면 링은 없다.

### 4.3 파문이 침묵한 제3자를 드러내는가?

**드러내지 않는다.** 파문 링은 지형 표면과 소리를 낸 본인만 드러낸다.
숨어서 가만히 있는 플레이어는 어떤 파문에도 보이지 않는다.

### 4.4 잔상 시스템 (Afterglow)

| 항목 | 값 |
|---|---|
| 대상 | **자기 SoundPulse만** (타인 파문 제외) |
| 범위 | **지형 모서리(edge)만** — 면 채움 없음 |
| 표시 금지 | **플레이어 / 오브젝트** |
| 지속 | **12초** |
| 밝기 | **15% → 0% 선형 감쇠** |

**차선책**: 모서리 렌더가 불가능할 경우에만 8% 밝기 / 8초.

### 4.5 로비 브리핑

라운드 시작 전 **맵 평면도를 30초간** 표시. 라운드 시작 시 사라진다.

## 5. 사운드 시스템

### 5.0 용어 정의

| 용어 | 정의 |
|---|---|
| **① 발생 반경** | SoundPulse가 생성되는 기본 범위. SoundType별 고정값 |
| **② 청취 반경** | 특정 역할이 인지 가능한 범위 = `발생 반경 × 역할 청취 배율 × 차폐 계수` |
| **③ 방향 표시 반경** | 인지한 소리에 방향 게이지가 나타나는 범위 |

**불변 조건**: `방향 표시 반경 ≤ 청취 반경`
방향 표시는 **인지한 소리에 대해서만** 나타나므로, 청취 반경을 넘을 수 없다.

**소음량 vs 노출 면적 — 두 지표를 통일하지 않는다 [신규]**

| 용어 | 공식 | 쓰이는 곳 | 측정 대상 |
|---|---|---|---|
| **소음량** | 발생 반경 × 지속시간 **(선형)** | 무성 생존상 채점(§10.3), 캠핑 누적 비교(§3.4-3) | 채점·비교용 밸런스 지표 |
| **노출 면적** | 발생 반경² × 지속시간 **(제곱)** | 소리 등급 격차의 **설계 근거** | 파문이 덮는 **면적 × 시간**(원 면적 πr²) |

> **두 지표는 서로 다른 것을 측정하므로 통일하지 않는다.**
> 노출 면적 기준 고함은 속삭임의 **126배**(1,210 vs 9.6),
> 소음량 기준으로는 **약 23배**(55 vs 2.4)다.
>
> 등급 격차를 설명할 때는 제곱이 옳고(면적이 실제로 제곱으로 늘어난다),
> 채점할 때는 선형이 옳다(제곱이면 고함 1회로 수상이 불가능해져 정상 플레이를 처벌한다).

### 5.1 소리 등급 전체표

아래 반경은 전부 **발생 반경**이다. 술래 청취 반경 = 발생 반경 × 1.2 (지속 × 1.5).

| 소리 | 발생 반경 | 지속 | 술래 청취 반경 | 방향 표시 | 발생 조건 |
|---|---|---|---|---|---|
| **속삭임** | 4m | 0.6초 | 4.8m | ✗ | 마이크 -50~-30 dBFS |
| **대화** | 9m | 1.2초 | **10.8m** | ✓ (10.8m) | 마이크 -30~-15 dBFS |
| **고함** | 22m | 2.5초 | **26.4m** | ✓ (26.4m) | 마이크 -15 dBFS 이상 |
| **걷기** | 2m | 0.4초 | 2.4m | ✗ | 이동속도 ≤5.0 m/s |
| **질주** | 6m | 0.8초 | 7.2m | ✗ | 이동속도 >5.0 m/s |
| **밸브 회전** | 12m | 각 밸브 회전 시간 | 14.4m | ✗ | 밸브 상호작용 중 |
| **비명** | 9m | 1.0초 | **10.8m** | ✓ (10.8m) | 술래 외침 22m 안 |
| **노크** | 9m | 1.2초 | **10.8m** | ✓ (10.8m) | 메아리 능력 |
| **호흡음** | 3m → 9m | 0.6초 | 3.6m → 10.8m | ✗ | 20초 정지 (§3.4-3) |

> **[수정] 방향 표시 반경**: 기존 문서의 `대화 13.5m / 고함 33m`는
> 발생 반경 × 1.5로 계산된 값이었다. 그러나 술래의 **반경** 청취 배율은
> ×1.2(대화 10.8m / 고함 26.4m)이므로, 기존 값은 **청취 반경보다 큰**
> 논리적 모순이었다 — 인지하지도 못한 소리에 방향 게이지가 뜨게 된다.
> **방향 표시 반경을 청취 반경과 동일하게 정정한다.**
> ×1.5는 반경이 아니라 **지속시간 배율**이며, 이 값은 그대로 유지한다.

**구분 불가 그룹 (의도적 설계)**

**대화 · 비명 · 노크**는 발생 반경 9m, 청취 반경 10.8m, 방향 표시 모두 동일하다.
술래는 셋을 구분할 수 없다. 이것이 §16-G 심리전의 근간이다.
(지속시간 1.2 / 1.0 / 1.2초 차이는 실사용에서 식별 불가능한 수준으로 간주한다.)

### 5.1-1 발소리 파문의 발생 주기 [신규 — 미정의 항목 해소]

기존 문서는 걷기·질주 파문의 **발생 주기**를 정의하지 않았다.
이 때문에 ①이동 중 파문이 몇 번 생기는지 구현할 수 없고,
②무성 생존상의 `Σ(소음량)`을 계산할 수 없었다.

**규칙: 발소리 파문은 "자신의 발생 반경과 같은 거리를 이동할 때마다" 1회 발생한다.**

| 소리 | 발생 반경 | 발생 간격 | 기준 속도 | 시간 간격 | 지속시간 | 결과 |
|---|---|---|---|---|---|---|
| 걷기 | 2m | **2m 이동마다** | 5.0 m/s | 0.40초 | 0.4초 | **끊김 없이 연속** |
| 질주 | 6m | **6m 이동마다** | 7.5 m/s | 0.80초 | 0.8초 | **끊김 없이 연속** |

**새로운 상수를 추가하지 않는다.** 발생 간격은 이미 존재하는 발생 반경 값을
그대로 재사용한 것이며, 그 결과 **발생 간격과 지속시간이 정확히 일치**해
이동 중 파문이 끊기지 않는다.

**시간이 아니라 이동거리 기준인 이유**
- 제자리 회전·미세 이동으로 파문을 양산하거나 회피할 수 없다 (§3.4-3 캠핑 방지와 정합)
- **1m당 소음량이 상수가 되어 무성 생존상이 계산 가능해진다**

**발생 간격은 재질 배율을 적용하지 않은 기본 발생 반경을 쓴다.**
간격이 재질마다 흔들리면 파문 점멸 리듬이 구역마다 달라져 혼란스럽고,
재질 효과가 소음량에서 상쇄되어 사라지기 때문이다.

| 대상 | 재질 배율 |
|---|---|
| **발생 간격** (2m / 6m) | **미적용 — 항상 고정** |
| **발생 반경** (실제 들키는 범위) | **적용** (§5.2) |

**1m당 소음량 (§10.3에서 사용)**

```
1m당 소음량 = (기본 반경 × 재질 배율 × 지속시간) ÷ 기본 발생 간격
            = 재질 배율 × 지속시간
```

| 소리 | 카펫 ×0.7 | 기준 ×1.0 | 타일 ×1.3 | 금속 ×1.5 |
|---|---|---|---|---|
| **걷기** (지속 0.4초) | **0.28** | **0.40** | 0.52 | 0.60 |
| **질주** (지속 0.8초) | 0.56 | **0.80** | 1.04 | 1.20 |

기준 재질에서 질주는 걷기의 **1m당 정확히 2배**다. (제곱 공식 시절에는 18배였다.)
그리고 **조용한 길(카펫)을 골라 걸은 플레이어가 무성 생존상에서 실제로 유리해진다** —
§5.2 재질 규칙이 어워드에도 정상 반영된다.

### 5.2 재질별 발소리 배율

**발생 반경**에 곱한다.

| 재질 | 배율 | 적용 구역 |
|---|---|---|
| 금속 그레이팅 | **×1.5** | 직원 통로, 계단 |
| 타일 | ×1.3 | 샤워장, 풀사이드, 유아풀 존, 세탁실 |
| 콘크리트 | ×1.0 | 기계실, 약품창고, 물탱크실 |
| 목재 | ×1.0 | 사우나 |
| 매트 / 카펫 | **×0.7** | 라커룸, 로비, 관람석, 라이프가드실 |
| 물 (수면 아래) | **파문 없음** | 메인 풀, 유아풀 |

### 5.3 차폐(Occlusion)

**청취 반경** 계산 시 적용한다.

| 지형지물 | 효과 |
|---|---|

| HardBlocker (무대 커튼) | 완전 차단. 파문 이벤트 미전송 |

```
청취 반경 = 발생 반경 × 재질 배율 × 역할 청취 배율 × (0.5 ^ 벽 통과 수)
```

### 7.3-2 잠수 피드백 — 상시 표시 + 2단계 경고 [수정]

**문제**: 기존 "게이지 3초 잔여 경고"는 경과 5.0초에 발동하는데 정상 수행은
4.0초에 끝난다. **성공하면 경고가 절대 뜨지 않아 피드백으로서 무의미**했다.

**해결**: 정상 수행 중에는 **상시 표시**로 정보를 주고, 지체했을 때만
**경고**가 단계적으로 켜지도록 분리한다. 새 게이지·새 시스템을 추가하지 않는다.

**선택한 방식: 잔여 숨 게이지 기준** (밸브 진행도 기준이 아님)

> 근거: 밸브 B에서 플레이어가 죽는 원인은 밸브 실패가 아니라 **질식**이다.
> 위험의 주체가 숨 게이지이므로 경고도 게이지에 걸어야 직관적이다.
> 또 숨 게이지는 잠수·비명 억제와 공유하는 단일 자원이라 이미 화면에 있다.

**① 상시 표시 (정상 수행 중 의미를 갖는 부분)**

| 요소 | 내용 |
|---|---|
| **귀환 한계선** | 숨 게이지 바의 **1.0초 지점에 고정 마커**. 부상에 필요한 시간이므로 "여기 아래로 가면 못 올라온다"를 항상 보여준다 |
| **밸브 진행 원형 게이지** | 회전 진행도 0→100%를 원형으로 표시 |
| **잔여 게이지 수치** | 숫자로 상시 표시 |

**② 2단계 경고 (지체했을 때만)**

**발동 전제 조건: 현재 상태가 `잠수`일 때만 평가한다.**
숨 게이지는 비명 억제와 공유하는 자원이므로, 이 조건이 없으면
육상에서 억제 2회(-6, 잔여 2초) 시에도 익사 경고가 뜬다. 그것은 오작동이다.

| 단계 | 발동 조건 | 표현 |
|---|---|---|
| **1단계 — 주의** | **상태 = 잠수** AND 잔여 게이지 ≤ **3.0초** | 게이지 바 황색 + 느린 심박음 |
| **2단계 — 위험** | **상태 = 잠수** AND 잔여 게이지 ≤ **1.0초** (귀환 한계선 도달) | 게이지 바 적색 + 빠른 심박음 + 화면 가장자리 vignette |

**해제**: 상태가 `잠수`에서 벗어나면(수면 또는 물 밖) 경고는 **즉시 해제**된다.
게이지 잔여량과 무관하다.

**귀환 한계선 마커도 동일하다** — 잠수 중에만 표시한다.

**③ 타임라인 검증**

*정상 수행 (4.0초 완료)*

| t | 잔여 게이지 | 단계 | 밸브 진행 | 경고 |
|---:|---:|---|---:|---|
| 0.0 | 8.0 | 진입 시작 | 0% | 없음 |
| 1.0 | 7.0 | 진입 완료 / 회전 시작 | 0% | 없음 |
| 2.0 | 6.0 | 회전 중 | 50% | 없음 |
| 3.0 | 5.0 | **회전 완료** / 부상 시작 | **100%** | 없음 |
| 4.0 | **4.0** | **부상 완료 · 성공** | 100% | 없음 |

→ **정상 성공 시 경고는 뜨지 않는다.** 대신 상시 표시(귀환 한계선·원형 게이지)가
전 구간에서 진행 상황을 알려준다.

*지체 수행 (회전 후 2초 머뭇거림)*

| t | 잔여 게이지 | 상태 | 경고 |
|---:|---:|---|---|
| 3.0 | 5.0 | 회전 완료 | 없음 |
| 4.0 | 4.0 | 수중 잔류 | 없음 |
| **5.0** | **3.0** | 수중 잔류 | **1단계 주의 발동** |
| 6.0 | 2.0 | 부상 시작 | 1단계 유지 |
| 7.0 | 1.0 | 부상 완료 · 성공 | 2단계 직전 |

*실패 (계속 수중 잔류)*

| t | 잔여 게이지 | 경고 |
|---:|---:|---|
| 5.0 | 3.0 | 1단계 주의 |
| **7.0** | **1.0** | **2단계 위험 — 지금 부상해도 간신히 도달** |
| 8.0 | 0.0 | **질식 페널티** (§3.4-1) |

**④ 설계 의도**

정상 수행에서는 **경고 없이 상시 표시만**으로 충분히 통제감을 준다.
1초라도 지체하면 t=5.0에 1단계가 켜지므로 **"지금 늦었다"를 즉시 안다.**
2단계(t=7.0)는 귀환 한계선과 일치해 **마지막 판단 지점**을 명확히 알린다.

**실패 처리**: 회전 완료 전 부상하면 **밸브 진행도 리셋**.
게이지 0 도달 시 질식 페널티(§3.4-1).

**게이지 0초 경계 처리 (판정 우선순위) [보완]**

`t = 8.0초`처럼 **부상 완료와 게이지 고갈이 같은 시점에 성립**하는 경우,
아래 순서로 판정한다.

| 순위 | 판정 | 처리 |
|---|---|---|
| **1** | **부상 완료** | 성립하면 **Valve B 성공으로 확정** |
| **2** | 게이지 고갈(질식) | 순위 1이 이미 성공 확정된 경우 **무시한다** |

> **정확히 게이지 0초에 부상이 완료되면 러너는 성공한다.**
> 부상 완료 판정이 질식 판정보다 항상 우선하며, 성공이 확정된 뒤의
> 고갈 판정은 적용하지 않는다.

**네트워크 지연 검증**: 여유 4.0초는 왕복 지연 200ms 기준 **20배 마진**이다.
지연으로 인해 성공이 불가능해지는 상황은 발생하지 않는다.
밸브 진행도는 **서버 권위**로 관리하며, 클라이언트는 예측 표시만 한다.

**UI 명세**
- 잠수 중 숨 게이지 **상시 표시**
- 밸브 회전 진행도 **원형 게이지**
- 2단계 경고: 잔여 3.0초 주의 / 잔여 1.0초 위험 (§7.3-2)
- 숨 게이지 바에 귀환 한계선(1.0초) 상시 마커
- 첫 실패 시 "부상하면 진행도가 초기화됩니다" 안내 1회

## 8. 승패 조건

### 8.0 러너의 세 가지 최종 상태

| 상태 | 정의 |
|---|---|
| **탈출** | 밸브 3개 개방 후 출구 접촉 |
| **태그** | 술래에게 태그당함 (메아리 전환) |
| **미탈출** | 시간 종료 시점에 살아 있으나 탈출하지 못함 |

### 8.1 승리 판정식

```
[라운드 종료 시점에 1회만 평가]

밸브 3개 전부 개방  AND  탈출 > (태그 + 미탈출)
    → 러너 승리
그 외 전부
    → 술래 승리
```

### 8.2 이 판정식의 성격 [수정]

이것은 **기존 승리조건인 `탈출 > 태그`의 시간 종료 상태를 명확히 처리하기 위한
판정 보완**이다. **"완전히 동일하다"고 말할 수 없다.**

**보완이 적용되는 조건**: `미탈출 > 0`인 경우, 즉 **시간 종료 시점에만** 발생한다.

| 상황 | 기존식 `탈출>태그` | 보완식 `탈출>(태그+미탈출)` | 차이 |
|---|---|---|---|
| 모든 러너가 탈출/태그로 확정 (미탈출=0) | 동일 | 동일 | **없음** |
| **시간 종료 · 탈출1 · 태그0 · 미탈출2** | **러너 승** | **술래 승** | **★ 여기서만 다름** |

기존식은 "탈출 1명 / 태그 0명"을 러너 승리로 판정했으나, 이는
남은 2명이 목표를 달성하지 못했음에도 승리가 되어 **HUD의 "탈출 2명" 표현과
어긋났다.** 미탈출 생존자를 목표 미달로 집계함으로써 이 불일치를 제거한다.

### 8.3 3 Runner 전수검증

| 탈출 | 태그 | 미탈출 | 판정 | 탈출≥2 | 일치 |

| 상황 | 처리 |
|---|---|

### 10.0 SoundType 대조표 — Shout ≠ Scream [수정]

어워드 판정에서 두 SoundType이 혼용되지 않도록 전체를 명시한다.
**`Shout`(고함)과 `Scream`(비명)은 완전히 별개의 SoundType이다.**

| SoundType | 한글 | 발생 반경 | 지속 | 발생 주체 / 조건 |
|---|---|---|---|---|
| `Whisper` | 속삭임 | 4m | 0.6초 | 플레이어 마이크 -50~-30 dBFS |
| `Conversation` | 대화 | 9m | 1.2초 | 플레이어 마이크 -30~-15 dBFS |
| **`Shout`** | **고함** | **22m** | **2.5초** | **플레이어가 직접 크게 말함** (마이크 -15 dBFS 이상) |
| `Footstep` | 걷기 | 2m | 0.4초 | 이동속도 ≤5.0 m/s, 2m 이동마다 |
| `Sprint` | 질주 | 6m | 0.8초 | 이동속도 >5.0 m/s, 6m 이동마다 |
| `Valve` | 밸브 회전 | 12m | 각 밸브 회전 시간 | 밸브 상호작용 중 |
| **`Scream`** | **비명** | **9m** | **1.0초** | **술래 외침의 22m 공포 반경 안에서 억제에 실패한 러너. 캐릭터 자동 SFX** |
| `Knock` | 노크 | 9m | 1.2초 | 메아리 능력 |
| `Breath` | 호흡음 | 3m → 9m | 0.6초 | 20초 정지 감지 (§3.4-3) |

> **`Shout`은 플레이어가 의도해서 내는 소리, `Scream`은 능력에 의해 강제로
> 발생하는 소리다.** 최다 비명상은 **`Scream`만** 집계한다.

### 10.0-1 최다 비명상 판정 명세 [수정]

```
최다 비명상 = 세션 내 SoundType.Scream 이벤트 발생 횟수가 가장 많은 러너
```

| 규칙 | 내용 |
|---|---|
| 집계 대상 | **`SoundType.Scream` 이벤트만** |
| **`Shout` 제외** | **고함 횟수는 판정에 일절 반영하지 않는다** |
| 억제 성공 시 | 숨 참기로 비명이 **발생하지 않았다면 집계하지 않는다** (이벤트 자체가 없음) |
| 공포 반경 밖 | 22m 밖은 비명이 발생하지 않으므로 집계 대상 없음 |
| 청취 여부 무관 | 술래가 10.8m 밖이라 **듣지 못했어도 비명 이벤트는 발생했으므로 집계한다** |
| 메아리 | **대상 아님** (메아리는 비명을 내지 않는다) |
| 동점 | 동점자 전원 공동 수상 |

> **주의**: 집계 기준은 "술래가 인지했는가"가 아니라 "비명 이벤트가 발생했는가"다.
> 10.8~22m 구간에서 지른 비명도 정상 집계된다.

### 10.5 최고의 거짓말상 — 인과관계 판정 [수정]

**기존 문제**: "30초 안에 9m 진입"만으로는 **노크 때문에 온 것**과
**우연히 지나간 것**을 구분할 수 없어 어워드가 오판됐다.

> **판정의 성격 [보완]**: 이 규칙은 실제 인과관계를 수학적으로 증명하는 것이 아니라,
> **노크에 의해 술래가 유인되었다고 간주할 수 있는 최소 조건을 충족하면 성공으로
> 판정하는 휴리스틱 규칙**이다.

**후보 비교**

| 후보 | 내용 | 판정 |
|---|---|---|
| **A** 접근 방향성 | 9m 밖 + 접근 + 30초 내 진입 | 우연 통과를 일부만 차단. "이미 그쪽으로 가던 중"을 못 거름 |
| **B** 목표 전환 | 직전에 다른 방향 → 이후 전환 + 진입 | 인과에 가장 근접하나 "전환"의 정의가 모호할 수 있음 |
| **C** 시간 단축 + 접근 | A와 사실상 동일 | A와 차이 없음 |
| **★채택** | **A + B 결합, 단 판정은 "거리 스칼라 변화" 하나로만** | 벡터 내적·AI 분석 불필요. 모호성 제거 |

**최종 판정식**

```
d(t) = 술래와 Knock 위치 사이의 거리

[감시 개시 조건]  Knock 발생 시점 t0에서
  ① d(t0) > 9m                     ← 아니면 감시를 시작하지 않는다
  ② d(t0) >= d(t0 - 2초)            ← 직전 2초간 접근 중이 아니었을 것

[감시]  t0부터 30초간 0.5초 간격 샘플링
  ③ 접근누적 += 0.5초   (직전 샘플보다 거리가 줄었을 때만)
  ④ d <= 9m 도달 시점에 접근누적 >= 3.0초  →  유인 성공

[감시 종료 — 전부 실패 처리]
  30초 경과 / 술래가 러너를 태그 / 라운드 종료
```

**사용하는 데이터는 거리·시간뿐이다.** 이동 벡터·시야·경로 분석을 쓰지 않는다.

| 상수 | 값 | 역할 |
|---|---|---|
| 진입 판정 거리 | **9m** | 노크 발생 반경과 동일 (§3.5) |
| 감시 시간 | **30초** | 기존 값 유지 |
| 사전 판정 창 | **2초** | ②의 "접근 중이 아니었음" 확인 구간 |
| 샘플 간격 | **0.5초** | 네트워크 위치 갱신에 충분 |
| 접근누적 하한 | **3.0초** | 스쳐 지나감과 실제 유인을 가르는 임계값 |

**8가지 예외 처리**

| # | 상황 | 판정 | 근거 |
|---|---|---|---|
| 1 | 우연히 지나감 | **실패** | 스쳐 가면 접근누적이 3.0초에 못 미친다 |
| 2 | 이미 그쪽으로 이동 중이었음 | **실패** | ②가 불만족. **유인이 아니므로 제외한다** (일관 적용) |
| 3 | Knock 직후 반대로 갔다가 복귀 | **성공** | 복귀 구간에서 접근누적 3.0초를 채우고 30초 내 진입하면 인정 |
| 4 | 짧은 시간에 여러 Knock | **1회만** | Knock마다 독립 감시하되, 진입 시 **가장 최근 성공 건 1개만** 집계하고 나머지 감시는 종료 |
| 5 | 같은 위치에서 반복 Knock | **1회만** | 동일 위치의 활성 감시는 **최신 1개로 갱신**. 스팸으로 횟수를 늘릴 수 없다 |
| 6 | Knock 후 술래가 태그 | **실패** | 감시 즉시 종료. 인과 확인 불가 |
| 7 | Knock 후 아무도 접근 안 함 | **실패** | 30초 경과로 종료 |
| 8 | Knock 시점에 이미 9m 이내 | **실패** | ①이 불만족해 **감시를 시작조차 하지 않는다** |

**대상**: 메아리 전용. 러너·술래는 이 어워드의 대상이 아니다.

> **Knock 자체의 규칙은 전혀 변경하지 않았다.** 발생 위치·9m·1.2초·대화 등급·
> 25초 쿨다운·라운드당 5회·20초 잠금 모두 §3.5 그대로다.
> 어워드는 Knock 이벤트를 **읽기만** 한다.

### 10.1 무성 생존상 계산식 [수정]

**기존 공식의 문제 (실제 수치 대입으로 확인)**

기존 `Σ(발생 반경² × 지속시간) ÷ 총 이동거리`를 10분 라운드 표준 모델
(이동 1,000m 기준)에 대입한 결과:

| 순위 | 플레이어 유형 | 점수 |
|---:|---|---:|
| 1 | 걷기만 함 | 0.800 |
| 2 | 비명 1회 | 0.881 |
| 3 | 걷기 + 짧은 질주 | 1.172 |
| **4** | **밸브 3개 수행** | **1.772** |
| 5 | 대화 10회 | 1.772 |
| 6 | 고함 1회 | 2.010 |
| 7 | 장시간 은신 | 2.960 |

**발견된 결함 2가지**

1. **밸브 수행자가 처벌받는다** — 게임의 목표를 달성한 플레이어가
   아무것도 안 하고 걷기만 한 플레이어보다 **2.2배 불리**하다.
   이것이 고함 문제보다 심각한 결함이다.
2. **고함 1회(1,210)가 걷기 756회분** — 제곱 때문에 격차가 비현실적으로 벌어진다.

### 10.2 세 가지 방법 비교

| 방법 | 내용 | 장점 | 단점 | 판정 |
|---|---|---|---|---|
| **A** | 현행 유지 `반경² × 지속` | 계산 단순, 새 상수 0개 | **밸브 수행자 처벌**, 고함 1회로 사실상 탈락 | ✗ |
| **B** | 소리 종류별 가중치 부여 | 세밀한 조정 가능 | **임의 상수 7개 이상** 추가. "왜 이 값인가" 답변 불가. 어워드치고 과도하게 복잡 | ✗ |
| **C** | 파문 발생 **횟수**만 세는 단순 상대평가 | 가장 단순 | 고함과 걷기를 동일 취급 → **"조용함"의 의미가 사라짐** | ✗ |
| **★추천** | **A의 최소 수정** — ①제곱→선형 ②밸브 회전 제외 | **새 상수 0개.** 기존 원칙 유지. 두 결함 모두 해소 | 없음 | **채택** |

### 10.3 최종 계산식

```
파문 소음량(1회) = 발생 반경 × 지속시간        ← 제곱을 선형으로
무성 점수 = Σ(본인이 발생시킨 파문 소음량) ÷ 총 이동거리(m)
           단, 밸브 회전음은 합계에서 제외
→ 생존자 중 무성 점수가 가장 낮은 플레이어 수상
```

**유지되는 원칙**

| 규칙 | 내용 |
|---|---|
| 발생 반경 | **재질 배율 적용 후**의 값 사용 (타일 걷기 = 2×1.3 = 2.6m) |
| 중복 집계 금지 | 한 파문이 여러 명에게 들려도 **1회만** 계산. 청취자 수 무관 |
| 본인 발생분만 | 자신이 직접 발생시킨 파문만 자기 점수에 반영 |
| 생존 요건 | **탈출 또는 미탈출**만 수상 대상. 태그당한 메아리는 제외 |
| 0 나누기 방어 | 총 이동거리 **1m 미만이면 수상 대상 제외** |
| **밸브 제외** | **목표 수행을 처벌하지 않기 위해 밸브 회전음은 계산에서 뺀다** |

**소리별 소음량 (기본 재질 기준)**

| 소리 | 계산 | 소음량 | 반영 |
|---|---|---:|---|
| 걷기 | 2 × 0.4 | **0.8** | ✓ |
| 질주 | 6 × 0.8 | **4.8** | ✓ |
| 속삭임 | 4 × 0.6 | **2.4** | ✓ |
| 대화 | 9 × 1.2 | **10.8** | ✓ |
| 고함 | 22 × 2.5 | **55.0** | ✓ |
| 비명 | 9 × 1.0 | **9.0** | ✓ (억제로 회피 가능) |
| 호흡음(1단계~최대) | 3×0.6 ~ 9×0.6 | **1.8 ~ 5.4** | ✓ (분모는 안 늘어 매우 불리) |
| **밸브 회전** | — | — | **✗ 제외** |
| 노크 | — | — | ✗ (메아리는 수상 대상 아님) |
| 찰칵이 | — | — | ✗ (파문 이벤트 없음) |

### 10.4 7개 플레이어 사례 검증

동일 모델(이동 1,000m 기준)에 최종 공식을 대입한 결과:

| 순위 | 플레이어 유형 | 점수 | 평가 |
|---:|---|---:|---|
| **1** | **걷기만 함** | **0.400** | 가장 조용함. 타당 |
| **1** | **밸브 3개 수행** | **0.400** | **목표를 수행해도 불이익 없음.** 결함 해소 |
| 3 | 비명 1회 | 0.409 | 강제 발생이므로 영향 미미. 타당 |
| 4 | 걷기 + 짧은 질주 | 0.438 | 질주는 시끄럽지만 치명적이지 않음. 타당 |
| 5 | 고함 1회 | 0.455 | **수상 가능권 유지.** 결함 해소 |
| 6 | 대화 10회 | 0.508 | 가장 시끄러운 정상 플레이. 타당 |
| **7** | **장시간 은신** | **0.760** | **압도적 최하위.** 캠핑 방지와 정합 |

**결론**

- 밸브 수행자가 1위 동률 → **정상적인 목표 플레이가 처벌받지 않는다**
- 고함 1회는 5위 → **한 번의 실수로 수상이 불가능해지지 않는다**
- 장시간 은신은 최하위 → **캠핑 방지 시스템과 모순되지 않는다**
- 대화 10회가 정상 플레이 중 최하위 → **"조용함"의 의미는 그대로 유지된다**

목표였던 **"조용하게 플레이한 사람을 칭찬하되, 정상 플레이를 했다는 이유로
수상이 불가능해지지 않는다"**를 충족한다.

## 12. 자주 묻는 질문

**Q. 말을 안 하면 앞이 전혀 안 보이나?**
완전 암전이 기본이다. 찰칵이(1회용)로 무음 확인이 가능하고, 걷기만 해도
발생 반경 2m가 잠깐 보인다. 잔상이 지나온 길의 모서리를 12초간 남긴다.

**Q. 가만히 숨어있으면 못 찾나?**
두 가지가 막는다. ① 술래 외침(45초 쿨다운) 22m 안이면 자동 비명 —
숨 참기(게이지 3초)로 억제 가능하나 잠수와 자원을 공유한다.
② **20초간 3m도 안 움직이면 호흡음이 시작되고 15초마다 커진다.**
숨는 플레이는 가능하되 무기한 정지는 불가능하다.

**Q. 술래는 왜 소리를 지르면 불리한가?**
22m 안 도망자가 모두 술래 위치를 안다. 45초 쿨다운에 1초 정지 선딜레이도 있다.
**결정적으로 술래의 비명 청취 반경은 10.8m까지다** — 10.8~22m 러너는
"들켰다"고 믿고 도망치지만 실제로는 안전하며, 그 질주 발소리(6m)가 진짜 단서가 된다.

**Q. 술래는 러너 3명을 다 잡아야 하나?**
아니다. **2명이면 즉시 승리 확정**이다. 남은 1명이 탈출해도 1 < 2다.

**Q. 메아리는 뭘 할 수 있나?**
노크(라운드당 5회)로 소리를 만들어 술래를 유인한다. 언제 쓸지가 실력이다.
4인 기준으로 메아리는 동시에 최대 1명뿐이다(§2.2).

**Q. 출구가 2개인데 술래가 왜 못 막나?**
직선 52m 떨어져 있어 술래가 반대편까지 **9.6초**가 걸린다.

## 14. 10분 라운드 템포

**각 구간은 사건 보장이 아니라 목표 감정과 예상 플레이 밀도다.**
강제 스크립트 이벤트를 추가하지 않는다.

| 구간 | 목표 감정 / 밀도 | 확률이 높아지는 이유 |
|---|---|---|
| 0~2분 | **낮은 긴장 / 탐색** | 목표가 진행되지 않아 소음원이 적다 |
| 2~4분 | **첫 조우가 일어나기 쉬움** | 밸브 회전(발생 12m)이 강한 소음원을 만든다 |
| 4~6분 | **정보와 태그 누적** | 파문 경험이 쌓여 동선을 예측하기 시작 |
| 6~8분 | **자원 및 승리조건 압박** | 숨 게이지·찰칵이·노크 5회 소진, 정지 감지 증폭 |
| 8~10분 | **탈출 결단** | 밸브 완료 시 양쪽 출구 개방음이 페이즈 전환을 알림 |

### 14.1 시스템적 압박 장치 5종

1. **밸브 소음 발생 12m** — 목표 진행과 노출이 직결
2. **정지 감지 증폭** — 시간이 갈수록 숨어있기 어려워짐
3. **자원 고갈** — 찰칵이 1회용, 숨 게이지, 노크 5회
4. **게이트 개방음** — 후반 페이즈 전환 통보
5. **메아리 등장** — 노크로 정보가 혼탁해짐 (4인 기준 최대 1명, §2.2)

**지루한 구간이 반복되면 시스템을 추가하지 말고 제한시간을 8분으로 줄인다.**

### 이번에 수정한 문제

1. **외침의 "22m"가 세 개념으로 뒤섞여 있었다** — 개발자가 "외침 1회에 누가
   무엇을 듣고 보는가"를 한 번에 알 수 없었다. **A) 외침 SoundPulse 발생 반경
   22m(차폐 적용) / B) 공포 반경 22m(능력 판정, 차폐 미적용) / C) 비명 청취 반경
   10.8m(차폐 적용)** 로 분리 정의하고, 거리별 반응표와 "누가 무엇을 얻는가"를
   §3.4-A·3.4-B에 신설했다. **수치는 하나도 변경하지 않았다.**
   특히 §5.1의 "고함 술래 청취 26.4m"는 **타인이 고함쳤을 때 술래가 듣는 값**이며
   술래 자신의 외침에는 적용되지 않는다는 점을 명시했다 — 술래가 자기 위치를
   노출하는 범위는 **러너 기준 22m**다.

2. **Valve B의 3초 경고가 구조적으로 무의미했다** — 정상 수행은 t=4.0에 끝나는데
   경고는 t=5.0에 발동해 **성공 시 절대 뜨지 않았다.**
   **상시 표시(귀환 한계선 1.0초 마커 + 원형 진행 게이지)와 2단계 경고
   (잔여 3.0초 주의 / 1.0초 위험)로 분리**했다. 경고 기준으로 밸브 진행도가 아닌
   **잔여 숨 게이지**를 선택한 근거는, 이 구간에서 플레이어를 죽이는 것이
   밸브 실패가 아니라 질식이기 때문이다. 정상·지체·실패 3종 타임라인을 §7.3-2에 계산했다.

3. **무성 생존상이 목표 수행자를 처벌하고 있었다** — 실제 수치를 대입한 결과,
   기존 공식에서 **밸브 3개를 수행한 플레이어(1.772)가 걷기만 한 플레이어(0.800)보다
   2.2배 불리**했다. 이것이 지적된 고함 문제(2.010)보다 심각한 결함이었다.
   방법 A/B/C를 비교한 뒤 **A의 최소 수정(①제곱→선형 ②밸브 회전 제외)**을 채택했다.
   **새 상수를 하나도 추가하지 않는다.** 7개 사례 재계산 결과 밸브 수행자가 1위 동률,
   고함 1회는 5위로 수상 가능권에 남고, 장시간 은신은 압도적 최하위가 됐다.

### 새롭게 발견하여 함께 수정한 문제

**1건 발견 — 수정 2가 만든 신규 모호성**

숨 게이지는 잠수와 **비명 억제가 공유하는 단일 자원**이다. 따라서 경고를
"잔여 게이지 3초"로만 정의하면 **육상에서 비명을 2회 억제(-6, 잔여 2초)했을 때도
익사 경고가 뜬다.** 이는 명백한 오작동이다.
→ 경고 발동 전제에 **"상태 = 잠수일 때만 평가"**를 추가하고,
잠수에서 벗어나면 잔여량과 무관하게 **즉시 해제**되도록 명시했다.
귀환 한계선 마커에도 동일 조건을 적용했다.
이 수정 후 1차부터 전체 검증을 다시 수행했다.
