# 수동 검증 절차 — 파문 · 밸브 · 라운드 · 태그

> 대상: `Assets/Scenes/Game.unity` Play 모드
> 자동 테스트로 덮을 수 없는 영역(렌더링·Physics·프레임률)만 다룬다. 로직은 EditMode 테스트 170케이스가 담당한다.
> 반복 가능하도록 절차를 고정해 둔 문서다 — 스프린트마다 이 순서대로 확인한다.

---

## 0. 준비

1. `Assets/Scenes/Game.unity`를 열고 Play
2. Hierarchy에서 `PulseSystem` 선택 → `Local Pulse Pipeline Behaviour` · `Pulse Visual Renderer` · `Valve Objective Tracker`가 붙어 있는지 확인. `Player`에는 `Valve Interactor`가 있어야 한다
3. Console 필터: `[Pulse]`(파문, 상세 로그 기본 꺼짐 — §5) / `[Valve]`(밸브) / `[Round]`(라운드 진행·판정) / `[Escape]`(탈출) / `[Tag]`(태그)

---

## 1. ⚠️ 가장 중요한 전제 — 청취점은 스폰 지점에 고정돼 있다

**시각 효과는 스폰 지점 주변에서만 보인다. 이것은 버그가 아니라 현재 구조상 당연한 동작이다.**

지금은 로컬 단일 클라이언트라 "남의 소리를 듣는 다른 플레이어"가 없다. 그래서 `LocalPulsePipelineBehaviour`가 **Start 시점의 플레이어 위치(스폰 지점, 약 `12, 0.05, 27`)에 가상 청취자 하나를 고정**해 두고 그 청취자 기준으로 판정한다(임시 스모크 리그).

판정 경로는 이렇다:

```
발소리 발생 (플레이어 현재 위치, 반경 2m/6m)
  → SoundPulseResolver.Resolve(pulse, 청취자=스폰지점)
  → straightDist > baseRadius 이면 즉시 null 반환   ← Core의 1차 컷
  → null이면 델리버리 자체가 없음
  → 렌더러는 그릴 것이 없음
```

즉 **플레이어가 스폰 지점에서 걷기 2m / 질주 6m를 벗어나면 아무것도 안 보이는 게 정상**이다. 렌더러의 문제가 아니라 Core의 거리 게이트가 먼저 걸러내는 것이며, 이 동작은 EditMode 테스트 `LocalPulsePipelineExpiryTests.SourceWalkingAwayFromFixedListener_LaterPulsesNeverAppear`가 이미 고정해 두었다.

> **따라서 아래 모든 절차는 "스폰 지점 반경 6m 이내"에서 수행해야 한다.**
> 실제 "멀리 있는 남의 발소리를 듣는" 기능은 네트워크 스프린트에서 청취자가 실제 원격 플레이어로 바뀔 때 완성된다.

**팁**: 스폰 지점을 잃어버렸으면 Play를 다시 시작하거나, Scene 뷰에서 `Player`의 시작 위치를 확인한다. Console 첫 줄에 `[Pulse] 디버그 청취점 고정: (12.0, 0.1, 27.0)` 이 찍힌다.

## 2. 기본 동작 — 파문 링이 보이는가

1. 스폰 지점에서 **제자리 또는 2m 이내로 조금씩** WASD 이동
2. 발소리마다 발밑에서 **원형 링이 퍼져 나가며 옅어지는지** 확인
3. `Shift` 질주 시 링이 **더 크게(6m) 퍼지는지** 확인

기대: 걷기는 작고 촘촘하게(0.4초 주기), 질주는 크고 느리게(0.8초 주기).

---

## 3. 차폐 검증 — GAP-2 분기가 눈에 보이는가 (T8의 핵심)

이번 스프린트에서 **처음으로** "차폐돼서 방향만 아는 것"과 "아예 안 들리는 것"이 시각적으로 구별된다.

1. 스폰 지점(로비) 근처에서 발소리를 내며 링이 보이는 것을 확인
2. **스폰 지점에서 6m를 벗어나지 않으면서** 벽 뒤(로비 벽 모서리 안쪽 등)로 이동
3. 화면 표시가 어떻게 바뀌는지 관찰

| 상황 | 기대 표현 |
|---|---|
| 벽 없이 트여 있음 | 발생 지점에 **월드스페이스 링** |
| 벽에 가려짐(반경 안) | 링 없이 **화면 가장자리 8방위 인디케이터(◆)** 만 |
| 반경 밖 | **아무것도 없음** |

세 번째와 두 번째가 구별되는 것이 이번 작업의 목표다. 인디케이터는 카메라가 바라보는 방향 기준으로 배치되므로, 제자리에서 마우스를 돌리면 ◆ 가 화면 가장자리를 따라 도는 것을 볼 수 있다.

## 4. 자연 소멸 확인 — Disappeared 없이 스스로 사라지는가

**배경**: 파문이 지속시간을 다 채우고 자연히 끝날 때는 `Disappeared` 신호가 오지 **않는다**(T7 설계, 스프린트 3 버그 조사에서 확정). 그래서 렌더러는 자체 타이머로 사라져야 한다. 이게 깨지면 파문이 화면에 영원히 남는다.

**절차**:
1. 스폰 지점에서 **한 걸음만 움직여 발소리 하나를 낸 뒤 즉시 멈춘다**
2. 가만히 서서 링을 관찰한다
3. 걷기 발소리는 **0.4초**, 질주는 **0.8초** 안에 완전히 사라져야 한다

기대: 링이 최대 반경까지 퍼지면서 투명해지다가 사라진다. **1초 넘게 남아 있으면 회귀 버그다.**

## 5. 색맹 모드 전환 (§19)

**방법 A — 디버그 키 (권장, 코드/인스펙터 수정 불필요)**

Play 중에 **`C` 키**를 누른다. Console에 `[Pulse] 색맹 모드 켜짐/꺼짐 (§19)` 이 찍히고, 그 즉시 파문 색이 바뀐다.

| 모드 | 러너 파문 색 |
|---|---|
| 기본 | 민트 `#35F0D0` |
| 색맹 | 노랑 `#F2E205` |

색 전환을 확실히 보려면 파문이 떠 있는 동안 눌러야 한다 — 발소리를 내면서 누르거나, `P` 키로 30개를 띄운 직후 누르면 확실하다.

**방법 B — 인스펙터**

`PulseSystem` → `Pulse Visual Renderer` → `Colorblind Mode` 체크박스. Play 중에 토글해도 즉시 반영된다.

**키 변경**: `PulseSystem` → `Local Pulse Pipeline Behaviour` → `Colorblind Toggle Key` 에서 바꿀 수 있다.

## 6. 성능 확인 (§15.5 동시 30개 @ 60fps)

1. `Game` 뷰에서 **Stats** 패널을 켠다(우상단 Stats 버튼)
2. Play 중 **`P` 키**를 누른다 → 청취점 주변에 파문 30개가 한꺼번에 생성된다
3. Stats의 FPS와 Console 로그의 프레임 시간을 확인한다

Console에 다음이 찍힌다:
```
[Pulse] 스트레스 테스트: 30개 생성 (활성 시각 오브젝트 N, 프레임 16.7ms)
```

기대: 60fps = 16.7ms 이하 유지. 파문 개수는 `Stress Test Pulse Count` 로 조절할 수 있다.

**더 정밀하게 보려면**: `Window > Analysis > Profiler`를 열고 `P` 를 누른 뒤 해당 프레임을 선택 → `GC.Alloc` 이 프레임당 0에 가까운지, `Camera.Render`/`GUI.Repaint` 중 어디에 시간이 쏠리는지 본다. (정밀 수치 실측 자체는 T6 스코프)

## 7. 밸브 상호작용 (스프린트 5, §6.1)

**밸브 위치**: 스폰(로비)에서 상당히 멀다. §10.1 배치 기준 — 기계실 `(36.4, 1, 19)`, 라이프가드실 `(34.4, 1, 11)`, 보일러 통로 `(40.5, 1, 13)`. 주황색(#FFB84D) 큐브를 찾아 이동한다.

### 7-1. 홀드 진행

1. 밸브에 **2.5m 이내**로 접근(GAP-10 결정값 — `ValveInteractor.Interaction Range`로 조정 가능)
2. **E를 누른 채 유지**
3. Console에 다음이 순서대로 찍히는지 확인:
```
[Valve] 기계실 밸브 회전 시작 (§6.1)
[Valve] 기계실 밸브 회전 중 17%
[Valve] 기계실 밸브 회전 중 33%
...
[Valve] 기계실 밸브 개방 완료
[Valve] 개방 1/3 — WinCondition: InProgress
```
기대: **3초**(§6.2 4인 기준) 만에 완료. 진행률 로그 간격은 `Progress Log Interval`(기본 0.5초).

### 7-2. 취소 조건 (GAP-9)

| 시도 | 기대 |
|---|---|
| 홀드 도중 **E를 뗀다** | `취소 — E를 뗌, 진행도 0으로 리셋` |
| 홀드한 채 **2.5m 밖으로 걸어 나간다** | `취소 — 범위 이탈, 진행도 0으로 리셋` |
| 홀드한 채 **범위 안에서만 움직인다** | **취소되지 않고 계속 진행** ← 기획서에 "이동 시 취소" 문구가 없어 규칙을 만들지 않았다 |

취소 후 다시 E를 누르면 **0%부터** 다시 시작한다(§6.1 부분 진행 저장 없음).

### 7-3. 역할 제약 (GAP-5)

1. Play를 멈추고 `Player` → `First Person Controller` → **`Role`을 `Echo`로 변경**
2. Play 후 밸브에서 E 홀드
3. 기대: `[Valve] … 상호작용 거부 — 역할 Echo (GAP-5: 메아리는 밸브 조작 불가)` 로그만 뜨고 **진행률이 전혀 오르지 않음**
4. 확인 후 `Role`을 `Runner`로 되돌린다

> 술래(`Seeker`)는 밸브를 돌릴 수 있다 — 기획서가 금지한 것은 메아리뿐이다.

### 7-4. 밸브 소음 (§5.1, 12m)

밸브 회전을 시작하면 **12m 반경 파문**이 발생한다(§6.1 "의도된 유인 장치"). 다만 §1의 청취점 제약 때문에, 스폰 지점에서 멀리 떨어진 밸브의 파문은 **화면에 보이지 않는 것이 정상**이다. 발생 여부는 `Log Deliveries`를 켜서 Console로 확인하거나, 네트워크 스프린트에서 청취자가 실제 플레이어로 바뀐 뒤에 눈으로 확인한다.

### 7-5. 승패 판정 연결 (§6.3)

밸브 3개를 모두 열면:
```
[Valve] 개방 3/3 — WinCondition: InProgress
[Valve] 밸브 전체 개방 — 배수로 게이트 Open, 탈출 가능 (§6.1). …
```

`InProgress`가 맞다 — **탈출·태그·라운드 타이머가 아직 미구현**이라 §6.3의 승리 조건이 성립하지 않는다. 판정식 자체를 확인하려면 `PulseSystem` → `Valve Objective Tracker` → `Runners Escaped`를 **1로 바꾼 뒤** 밸브를 열어본다 → `WinCondition: RunnersWin` 이 나와야 한다.

## 8. 라운드 진행 — 탈출과 시간 초과 (스프린트 6, §6.2/§6.3)

이제 **게임이 끝난다.** Play 시작 시 Console에 다음이 찍힌다:
```
[Round] 라운드 시작 — 제한시간 600초 (§6.2), 상태 InGame
```
이후 30초마다 `[Round] 남은 시간 …초`.

### 8-1. 게이트가 닫힌 상태에서는 탈출 불가 (§6.1)

1. 밸브를 **열지 않은 채** 배수로 출구의 탈출 지점(주황 발판, `40.5, 0.3, 5`)으로 이동
2. 기대: `[Escape] 배수로 게이트가 아직 닫혀 있다 — 밸브 3개를 모두 열어야 탈출할 수 있다 (§6.1)`
3. 라운드는 계속 진행된다

### 8-2. 러너 승리 경로 (§6.3) — 이번 스프린트로 처음 성립

1. 밸브 3개를 모두 연다(§7 절차) → `[Valve] 밸브 전체 개방 — 배수로 게이트 Open, 탈출 가능 (§6.1)`
2. 탈출 지점으로 이동
3. 기대:
```
[Round] 탈출 — playerId=1 (누적 1명)
[Round] 라운드 종료 — 판정: RunnersWin (밸브 3/3, 탈출 1명, 남은 시간 …초) → 상태 RoundEnd
```
`InGame → RoundEnd` 전이(§15.4)까지 로그로 확인된다.

### 8-3. 시간 초과 → 술래 승리

전체 10분을 기다리기 어려우므로 `PulseSystem` → `Round Coordinator` → **`Round Duration Seconds`를 10~20초로 줄여** 테스트한다.

기대:
```
[Round] 제한시간 종료 (§6.2)
[Round] 라운드 종료 — 판정: SeekerWin (밸브 0/3, 탈출 0명, 남은 시간 0.0초) → 상태 RoundEnd
```

**만료는 정확히 1회만** 발생해야 한다 — `제한시간 종료` 로그가 두 번 이상 찍히면 회귀 버그다.

### 8-4. 판정 우선순위 (§6.3 if/else 순서)

짧은 제한시간(예: 20초)으로 두고, **시간이 끝나기 전에 밸브 3개 개방 + 탈출**을 완료해 본다.
기대: 시간이 그 뒤에 만료돼도 판정은 `RunnersWin`으로 **고정**된다(탈출은 취소되지 않는 달성).

### 8-5. 태그 승리 경로는 아직 닫혀 있다

태그 판정(§14.1)은 다음 스프린트다. §6.3의 `allRunnersTagged` 분기를 확인하려면 `Round Coordinator` → **`All Runners Tagged`** 를 체크한다 → 즉시 `SeekerWin`.

## 9. 태그 판정 (스프린트 7, §3.1)

**대역 도망자**: 로컬은 플레이어가 한 명뿐이라 태그할 상대가 없다. 그래서 로비 인근에 민트색 캡슐 3개(`Runner_A/B/C`, 대략 `15,27` · `12,25.5` · `16.5,25`)를 대역으로 놓았다 — **실제 게임플레이 기능이 아니라 검증용**이며 네트워크 스프린트에서 실제 플레이어로 대체된다.

### 9-1. 준비 — 술래 역할로 전환

1. Play를 멈추고 `Player` → `First Person Controller` → **`Role`을 `Seeker`로 변경**
2. Play (태그는 술래만 할 수 있다 — §3.1)

### 9-2. 태그 발생

1. 대역 도망자 캡슐에 **1.2m 이내**로 접근
2. 기대: 즉시 `[Tag] 태그 — targetId=101 메아리로 전환 (§3.1) [1/3]`
   - **키 입력 불필요** — §3.1이 "접촉 트리거, 1회 접촉 즉시 확정"이라 접근만으로 발동한다
3. 같은 캡슐에 다시 접근해도 **추가 로그가 없어야 한다**(이미 메아리 = 태그 불가)

### 9-3. 일부만 태그 — 라운드가 끝나지 않는지

1과 2번 캡슐만 태그하고 멈춘다.
기대: `[2/3]`까지만 찍히고 **라운드 종료 로그가 없다**.

### 9-4. 전원 태그 → 즉시 술래 승리 (시간 만료를 기다리지 않음)

3번째 캡슐까지 태그한다.
```
[Tag] 태그 — targetId=103 메아리로 전환 (§3.1) [3/3]
[Round] 라운드 종료 — 판정: SeekerWin (밸브 0/3, 탈출 0명, 태그 3/3, 남은 시간 ...초) → 상태 RoundEnd
```
**남은 시간이 넉넉히 남아 있는데도 즉시 종료되는 것**이 핵심이다.

### 9-5. 혼재 경계 케이스 (가장 중요)

탈출과 태그가 섞였을 때 §6.3 우선순위를 확인한다.

1. `Role`을 `Runner`로 되돌리고 밸브 3개를 모두 연다
2. 탈출 지점으로 가서 탈출 → `RunnersWin`

§6.3의 if/else 순서상 **탈출(첫 분기)이 태그보다 우선**한다. 탈출은 게이트 개방 이후에만 가능하므로, 탈출이 성립하는 순간 이미 러너 승리 조건이 충족돼 있다. 이 우선순위는 EditMode 테스트 `EscapeWithValvesComplete_BeatsRemainingTags`가 고정한다.

> 참고: 대역 도망자는 움직이지 않으므로 "일부 탈출 + 일부 태그"를 로컬에서 동시에 만들기는 어렵다. 해당 경계는 EditMode 테스트로 검증했다.

### 9-6. 태그 없이 §6.3 술래 분기만 확인하려면

`Round Coordinator` → **`Force All Runners Tagged`** 체크 → 즉시 `SeekerWin`.
