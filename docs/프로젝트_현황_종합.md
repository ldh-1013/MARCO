### 2.2 FishNet Unity 6000.5 호환성 패치 (핵심 작업)

Unity 6000.5.4f1에서 FishNet 4.7.2가 그대로 컴파일되지 않음 — 두 가지 Unity 6.5 API 폐기가 원인.

1. `Object.GetInstanceID()` → `EntityId` 전환, 부호 검사 관용구 대체 불가
2. `Scene.handle`의 `int` 암시적 변환 제거 → `SceneHandle` 구조체로 전환

**조치**: 씬 핸들 저장 타입을 `int`→`ulong`(raw data)로 8개 파일에 걸쳐 전면 수정, `NetworkObserver.cs`는 `#if UNITY_6000_5_OR_NEWER` 분기 처리. FishNet 공식 저장소에는 아직 이 패치가 없음 — 이 프로젝트가 자체 대응한 것.

**검증**: Unity 에디터 없이 `dotnet build`로 csproj 12개 전부 컴파일 에러 0 확인, 리플렉션 러너로 Core.Tests 실행해 통과 확인.

### 3.16 스프린트 14 — 발소리 파문 네트워크화 (네트워크 2단계 마무리, §5.6/§14.3)

마지막 미동기화 시스템. 로컬 스모크 리그(고정 청취자 id=999)로만 돌던 파문이 **실제 원격 플레이어에게 전달**된다.

**구조가 다른 이유**: 밸브·태그·라운드·역할은 "상태 하나를 전원에게 똑같이" → SyncVar 하나로 충분. 파문은 GAP-2(좌표 vs 방위)·GAP-3(청취자별 재판정) 때문에 **청취자마다 내용이 다르다** → 브로드캐스트 불가, **`[TargetRpc]`로 청취자별 개별 전송**(§14.3 "Server → 해당 리스너만"이 명시).

**판정·시각화를 하나도 새로 만들지 않았다**: ① `ActivePulseTracker.Tick(now, listeners, probe)`가 이미 청취자 목록을 받는 시그니처(주석에 "Net 레이어가 매 Tick 구성해 넘긴다") ② `TrackedPulse.LastResults`가 이미 `Dictionary<청취자ID, ...>`라 **트래커 1개로 전원 처리**(청취자별 인스턴스 불필요) ③ `PulseVisualRenderer.Apply(in PulseDelivery, float)`를 그대로 재사용(렌더 코드 0줄 추가) ④ 렌더러 자체 만료 타이머 덕에 **시계 동기화 불필요**.

- **신규 Core**: `SoundPulse/ServerPulseDriver.cs`(§5.1 표 서버 재계산 + 트래커 위임), `Net/IPulseNetworkBridge.cs`(+`IPulseDeliverySink`), `SoundPulse/PulseNetworkRegistry.cs`(프로브·싱크 지연 바인딩).
- **신규 Net**: `PulseNetworkSync.cs` — ServerRpc 수집 → `RoleNetworkSync.Spawned`로 청취자 스냅샷(**스프린트 13 배정 역할** 사용 → §5.7 배율이 진짜 역할 기준) → TargetRpc 개별 전송.
- **수정 Presentation**: `LocalPulsePipelineBehaviour`(네트워크 시 로컬 틱 정지 + 서버 전달 + 프로브 등록), `PulseVisualRenderer`(`IPulseDeliverySink` 구현·자기등록, 렌더 로직 무변경).
- **신규 Editor**: `NetworkPulseSetupTool.cs`(`Setup Network Pulse`).
- **GAP-24**: 클라는 **소리 종류만** 주장 — 반경·지속은 서버가 §5.1 표에서 재계산, 위치는 `caller.FirstObject`, 발생원 ID는 `caller.ClientId`. 밸브·태그보다 **강한** 서버 권위(클라가 반경 부풀리기·발소리 위장 불가, 테스트로 고정). **GAP-25**: 밸브 소음(12m)도 같은 경로에 포함 — 빼면 네트워크에서 밸브가 무음이 되어 §6.1 유인 설계가 붕괴(스프린트 5와 같은 판단).

## 6. 검증 방법론 메모 (재사용 가능한 프로세스)

이 프로젝트는 Unity 에디터에 실시간 연결하지 않고 파일 조작 + 오프라인 컴파일 검증으로 진행했다. 핵심 장치:

- **스크래치패드 `CoreVerify.csproj` / `PresentationVerify.csproj`**: Unity가 생성하는 `Core.csproj` 등은 소스 파일을 명시적으로 나열하고 에디터가 재임포트하기 전까지 갱신되지 않는다(1회 "헛빌드" 사고 발생 후 발견). 이를 우회하기 위해 `Assets/_Project/**/*.cs`를 glob으로 잡는 별도 csproj를 만들어, Unity 관리 DLL(`C:\Program Files\Unity\Hub\Editor\6000.5.4f1\...`)을 그대로 참조해 컴파일한다.
- **리플렉션 기반 테스트 러너**: `[Test]`/`[TestCase]` 속성을 리플렉션으로 찾아 실행하는 자체 러너로 nunit.framework.dll만 있으면 Unity Test Framework 없이도 테스트를 돌릴 수 있다.
- **meta 파일 수기 생성**: 배경 자동 생성기가 불완전한 meta(1줄짜리)를 만들거나 GUID를 중복시키는 문제를 여러 차례 발견 → 매 작업 후 GUID 중복 검사 스크립트로 전수 검증하는 루틴 확립.
- **씬 YAML 직접 조작**: ProBuilder 없이 큐브 프리미티브로 그레이박스를 만들 때, fileID 중복·참조 무결성·SceneRoots 등록을 매번 파이썬 스크립트로 검증.

이 방법론 덕분에 Unity 에디터가 실제로 열리기 전에 컴파일 에러와 로직 결함 대부분을 잡아낼 수 있었지만, **에디터 전용 동작(렌더링·입력 실제 반응·프로파일링)은 여전히 사람이 직접 열어서 확인해야 한다.**
