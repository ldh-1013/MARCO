## 1. 게임 개요

| 항목 | 내용 |
|---|---|
| 가제 | 마르코! (MARCO!) |
| 장르 | 비대칭 음성 술래 호러 파티 |
| **정식 밸런스 기준** | **4인 (술래 1 + 도망자 3)** — 이 문서의 모든 수치는 이 기준으로 확정된다 |
| 인원 | 최소 2 / **권장 4** / 최대 6 (v1.x: 8~10인, 술래 2인) |
| 플랫폼 | PC(Steam), Windows |
| 한 판 길이 | 6~12분 (인원별 상이, 9절 참조) |
| 핵심 훅 | 말해야 앞이 보이는데, 말하면 술래가 듣는다 |
| 제작 전제 | 1인 개발(+Claude Code) · Unity 6 · Steam PC 유료 ₩6,000~15,000 · MVP 2~3개월/출시 6개월 내 · 호스트 기반 네트워킹 |

### 1.1 인원 확장 기준 [갱신]

**현재 버전의 모든 밸런스 수치와 승리조건은 도망자 3명 기준으로 잠근다.**

| 구분 | 상태 |
|---|---|
| **4인 (도망자 3)** | **정식 밸런스 사양.** 모든 수치가 이 기준으로 확정됨 |
| 5~6인 (도망자 4~5) | **확정 밸런스가 아니다.** 향후 **확장 가능 구조**로만 열어둔다 |

도망자가 4~5명이 되면 승리 목표 인원(현재 "탈출 2명", 8절)을 **별도로 재계산해야 한다.**
이 계산은 현재 버전에서 확정하지 않는다. 6.2절 인원별 표는 그 재계산을 위한 참고 자료다.

### 1.2 4인 기준에서만 성립하는 구조적 사실 [갱신]

**태그 2명 도달 시 라운드가 즉시 종료**되므로(8절), 도망자 3명 기준에서는
**플레이 중 동시에 존재하는 메아리가 최대 1명**이다.

| 태그 인원 | 메아리 수 | 상태 |
|---|---|---|
| 0명 | 0 | 진행 중 |
| 1명 | **1** | 진행 중 |
| 2명 | — | **라운드 즉시 종료** |

따라서 아래 서술은 **5~6인 확장 시에만 의미를 갖는다**(삭제하지 않고 보존한다).

- 메아리끼리 서로 보임 (16절)
- 메아리끼리 자유 음성 대화 (3.2절)

**4인 기준 라운드 전체의 노크 최대 발생량은 5회다**(메아리 1명 × 5회).

## 2. 핵심 재미 루프

**핵심 게임 루프 (변경 금지)**

```
완전한 암전 → 소리 발생 → SoundPulse → 제한적인 시야 확보 → 위치 노출 → 추적/회피
```

아래 2.1~2.3은 이 루프를 시간 단위별로 풀어 쓴 것이다.

### 2.1 30초 루프 (순간의 재미)

```
[불안: 암전] → [결단: 속삭임 or 한 걸음] → [정보: 파문으로 지형/술래 확인]
    → [대가: 방금 소리가 위치 광고] → (다시 침묵) → 반복
```

발화라는 인간의 기본 행동이 매 순간 리스크-리턴 도박이 되도록, 아래 3개 시스템이 이 루프를 지탱한다.

- **소리 등급 시스템** (5절) — 등급이 높을수록 **노출 면적**과 정보량이 함께 커지는 구조 (§5.0-1)
- **파문 렌더링** (5.3) — 0~80ms 이내 시각 피드백으로 "방금 그게 위험했다"를 즉시 체감
- **술래 파문 강화 인지** (3절, 5.7) — 같은 소리라도 술래에게는 실제로 더 멀리·더 오래 감지되는 기능적 우위로 작용

### 2.2 한 판 루프 (8~12분)

| 페이즈 | 길이(4인 기준) | 목표 | 종료 조건 |
|---|---|---|---|
| 은신 페이즈 | ~90초 | 지형·밸브 위치 파악, 초기 산개 | 첫 밸브 상호작용 시작 |
| 소음 작업 | ~5~7분 | 밸브 3개 회전 완료 | 밸브 3개 모두 열림 |
| 추격과 희생 | 병행 | 술래의 발각·태그, 메아리 전환 | 전원 태그 또는 시간 종료 |
| 탈출 러시 | 최종 1~2분 | **두 출구(배수로·정문) 중 하나 도달** | 탈출 2명 달성 또는 시간 종료(8절) |

### 2.3 메타 루프 (재접속 동기)

- 술래 로테이션 3판 1세트 (~30분)
- 어워드 3종: 최다 비명상 / 무성 생존상 / 최고의 거짓말상 (v1.x: 통계 누적)
- 뮤테이터 투표로 같은 맵 문법 재조합 + 파문 스킨 해금

## 3. 역할(Role) 시스템 상세

### 3.1 역할별 파라미터

| 파라미터 | 리스너(술래) | 도망자 | 메아리(탈락자) |
|---|---|---|---|
| 기본 이동속도 | 5.0 m/s × 인원별 보정(1.05~1.12) → **4인 기준 5.4 m/s(추격)** | 5.0 m/s | **6.0 m/s** (관전형, 콜라이더 없음) [갱신] |
| **잠행 이동속도** | **3.5 m/s** — 발소리가 걷기급 2m로 낮아진다 [신설] | 해당 없음 | 해당 없음 |
| 질주 이동속도 | 해당 없음(질주=상시 보정 반영) | 7.5 m/s | 해당 없음 |
| **질주 스태미나** | 해당 없음 | **5초. 소진 시 3초간 이동속도 -20%** [신설] | 해당 없음 |
| 발소리 | 상시 질주급 6m (5.4 > 5.0 기준) / **잠행 시 2m** | 걷기 2m / 질주 6m | **없음** |
| 파문 인지 배율 | 반경 ×1.2, 지속 ×1.5 (5.7절 — 실제 탐지 판정에 반영되는 기능적 수치) | 표준(×1.0) | **거리·차폐 무시**(3.6절 소나) [갱신] |
| 방향 게이지 | 도망자 대화·고함 등급 발화 시 벽 너머 대략적 방향 표시(호스트 권위 계산, 상세는 3.4절) | 없음 | 없음 |
| 태그 판정 | 접촉 트리거, 반경 1.2m, 1회 접촉 즉시 확정 | 태그 대상 | 태그 불가(비활성 콜라이더) |
| 특수 능력 | **외침(3.5절)** — 45초 쿨다운 [신설] | 잠수(풀맵 한정, 숨 게이지 8초, 회복 로직 5.9-1절) | 노크(**25초 쿨다운, 라운드당 5회**, 3.2절) [갱신] |
| 사망/탈락 처리 | 해당 없음 | 태그 1회 → 메아리로 즉시 전환 | 해당 없음(최종 상태) |

> **[갱신] 메아리 이동속도 8.0 → 6.0 m/s.** 도망자 질주(7.5)보다 느려야
> 메아리가 러너를 따라다니며 실시간 중계하는 플레이가 성립하지 않는다.

### 3.2 메아리(Echo) 상세 스펙

메아리는 "탈락 = 관전"이 아니라 "탈락 = 다른 방식의 참가"로 설계된 상태다.

- **이동**: 자유 비행형 유령 카메라, 충돌 없음(벽 통과), 이동속도 **6.0 m/s** [갱신]
- **음성**: 생존자에게 들리지 않음. 메아리끼리는 별도 사망자 채널로 자유 대화
  (1.2절 — 4인 기준에서는 메아리가 최대 1명이라 실사용은 5~6인 확장 시)
- **가시성**: 러너·술래에게 **렌더링되지 않는다.** 메아리끼리는 서로 보인다 [갱신]
- **태그 직후**: **3초 암전 + 조작 불가** [신설]
- **노크 능력**:
  - 쿨다운 **25초**, **라운드당 정확히 5회(재충전 없음)**, 메아리 전환 후 **20초간 사용 불가** [갱신]
  - **발생 위치: 메아리의 현재 위치.** 지점 클릭 방식은 채택하지 않는다 [갱신]
  - 발생 소음: "대화" 등급과 동일 취급 (반경 9m, 지속 1.2초) — 술래·도망자 모두 인지 가능
  - **자기 파문은 자기 화면에 표시하지 않는다**
  - 술래가 노크와 실제 대화·비명을 구분할 **시각적·청각적 단서는 없다**
  - 전략적 의미: 도망자를 도와 술래를 유인하거나, 반대로 도망자를 낚아 술래에게 정보를 흘릴 수도 있음(플레이어 재량)
- **상태 전이**: `Runner --[Tagged]--> Echo` (역방향 전이 없음, 라운드 종료까지 유지)

> **라운드당 5회 하드캡은 타협하지 않는다.** 충전형·무제한으로 되돌리지 않는다.
> 노크는 쿨다운마다 누르는 방해 버튼이 아니라, 5번의 기회를 언제 쓸지 판단하는 도구다.

#### 3.2-1 메아리의 시야 — 소나 [갱신: 미니맵 대체]

**미니맵 시스템은 존재하지 않는다.** 기존 "미니맵/탑다운 뷰"는 전면 삭제하고
아래 소나 시야로 대체한다.

| 항목 | 내용 |
|---|---|
| 지형 | **끝까지 보이지 않음** |
| 파문 관측 | **맵 전체의 SoundPulse를 거리·차폐에 관계없이 관측** |
| 표현 | **단색 저채도 윤곽** |
| 발생자 식별 | **불가능** |
| 미니맵 / 생존자 위치 표시 | **없음** |

**정보량 제한** — 새 UI를 추가하지 않고 기존 SoundPulse 지속시간·렌더링 규칙으로 제한한다.

| 항목 | 초기 밸런스값 | 테스트 범위 |
|---|---|---|
| 파문 표시 시간 | 본래 지속시간 그대로 (0.4~2.5초) | 고정 |
| 잔류 흔적 | **소멸 후 3초간 감쇠** | 2~5초 |
| 동시 표시 상한 | **최근 8개** | 6~12개 |

> 상한을 두는 이유는 파문이 화면에 무한히 쌓이면 메아리가 사실상
> **"소리로 그린 지도"**를 갖게 되기 때문이다. 목표는 최근 전황은 읽되
> 장시간 누적 정보를 축적하지 못하게 하는 것이다.

**플레이테스트 판단 기준**

| 관찰 | 조치 |
|---|---|
| 메아리가 화면만 보고 러너 동선을 예측한다 | 6개로 축소 |
| 메아리가 "방금 어디서 소리 났는지" 놓친다 | 10~12개로 확대 |
| 화면이 파문으로 가득 차 개별 구분이 안 된다 | 축소 + 잔류 2초 |
| 메아리가 노크 위치를 못 정한다 | 잔류 5초로 확대 |

**금지**: 지형 표시, 발생자 식별, 러너 위치 자동 추적, 미니맵.

#### 3.2-2 메아리의 방향 감각 [신설]

메아리는 지형을 볼 수 없고 노크가 현재 위치에서 발생하므로 최소한의 방향 감각이 필요하다.
**미니맵·지도·러너 위치 표시·전체 맵 HUD는 추가하지 않는다.**

| 수단 | 내용 |
|---|---|
| **8방위 나침반** | 화면 가장자리에 아주 흐린 8방위. **바라보는 방향만** 알려주며 위치·지형은 알려주지 않는다 |
| **자기 실루엣 발광** | 메아리 본인의 몸이 약하게 발광해 자기 이동을 체감(16.2 역할별 림라이트 재사용) |

나머지 공간 파악은 관측되는 파문의 위치 관계로 스스로 추론한다.

### 3.3 상태 다이어그램 (역할)

```
[RoleAssign]
   ├─ Seeker(1) ──────────────────────────────► [InGame: Seeker]
   └─ Runner(N) ──────────────────────────────► [InGame: Runner]
                                                       │ Tagged (콜라이더 접촉)
                                                       ▼
                                                 [InGame: Echo]
                                                       │ RoundEnd
                                                       ▼
                                                 [ResultScreen]
```

### 3.4 방향 게이지 상세 스펙

3.1의 "방향 게이지"는 아래 규칙으로 확정한다. 이 규칙이 없으면 술래가 사실상 무제한 사거리로 도망자 위치를 아는 것처럼 오해될 소지가 있어 명확히 못박는다.

**트리거 조건**

- **속삭임 등급은 트리거하지 않는다.** 대화·고함 등급만 트리거된다 — "육성 발화"의 실제 정의는 이 둘뿐이다.
- 밸브 회전음, 발소리, 노크는 방향 게이지 트리거 대상에서 제외된다(이 게이지는 어디까지나 "말"에 대한 술래 전용 정보 우위).

**사거리 캡 [갱신 — 청취 반경과 동일하게 정정]**

| 발화 등급 | 발생 반경(5.1) | 술래 청취 반경 (×1.2) | 방향 게이지 최대 사거리 |
|---|---|---|---|
| 대화 | 9m | 10.8m | **10.8m** |
| 고함 | 22m | 26.4m | **26.4m** |

> **[갱신] 기존 `대화 13.5m / 고함 33m`은 발생 반경 × 1.5로 계산한 값이었다.**
> 그러나 술래의 **반경** 청취 배율은 ×1.2(5.7절)이므로, 기존 값은 **청취 반경보다 큰**
> 논리적 모순이었다 — 인지하지도 못한 소리에 방향 게이지가 뜨게 된다.
> **방향 표시 반경을 청취 반경과 동일하게 정정한다.**
> ×1.5는 반경이 아니라 **지속시간 배율**이며, 그 값은 그대로 유지한다(5.0절 불변 조건).

> 맵 전체(52m×40m, 대각선 약 65.6m)를 기준으로 고함조차 맵 전체를 커버하지 못하도록 설계해, 한 번의 실수가 맵 전체에 광고되는 최악의 시나리오를 방지한다.

**정밀도**

- 정확한 좌표가 아니라, 술래 기준 발화 지점 벡터를 8방위(N/NE/E/SE/S/SW/W/NW) 중 최근접 방위로 스냅해 화면 가장자리 링의 해당 구간만 밝힌다.
- 표시 지속시간은 5.7절에서 계산되는 `perceivedDuration`과 동일(고함 기준 최대 2.5초 × 1.5배 = 3.75초).
- 동일 발화자에 대한 게이지 갱신은 최소 0.5초 쿨다운을 둔다(판정 자체가 아니라 UI 재생 스팸 방지 목적).

### 3.5 술래 전용 — 외침 [신설]

술래가 외침을 사용하면 **22m 안의 살아있는 도망자가 자동으로 짧은 비명을 낸다.**
**플레이어가 직접 "폴로"라고 말하는 방식은 채택하지 않는다.** 캐릭터 SFX로 자동 발생한다.

**발동**

| 항목 | 값 |
|---|---|
| 선딜레이 | **1초 정지** (선딜레이 중 이동하면 취소, 쿨다운 소모 없음) |
| 쿨다운 | **45초** (선딜레이 완료 시점부터 계산) |
| 술래가 발생시키는 소리 | **고함 등급 SoundPulse**(5.1절) — 발생 반경 22m |

**세 가지 "22m"를 분리한다**

외침 하나에 22m가 여러 번 등장하지만 **서로 다른 세 개념**이다. 구현 시 같은 것으로 취급하지 않는다.

| # | 개념 | 값 | 성격 | 차폐 적용 |
|---|---|---|---|---|
| **A** | 외침 SoundPulse 발생 반경 | **22m** | 술래가 만드는 **소리 이벤트**. 고함 등급 | **적용** |
| **B** | **공포 반경** | **22m** | 자동 비명을 트리거하는 **능력 효과 범위**. 소리가 아니다 | **미적용**(순수 직선거리) |
| **C** | 비명 청취 반경 | **10.8m** | 술래가 그 비명을 인지하는 범위 = 9m × 1.2 | **적용** |

> **A와 B가 우연히 같은 22m일 뿐 서로 다른 판정이다.** A는 소리라 벽을 지나면 감쇠하지만,
> B는 능력 판정이라 벽 뒤 도망자도 놀란다. 그 비명은 차폐로 감쇠돼 술래에게 닿지 않는다.

**22m 안 도망자의 거리별 반응**

| 거리 | 도망자 반응 | 술래가 비명 인지 |
|---|---|---|
| **0 ~ 10.8m** | 비명 | **인지** |
| **10.8 ~ 22m** | 비명 | **인지 못함** |
| **22m 초과** | 비명 없음 | 인지 불가 |

10.8~22m 구간의 도망자는 자기가 비명 지른 것을 알기에 "들켰다"고 믿지만 실제로는
술래에게 아무 정보도 가지 않는다. **이 정보 비대칭이 공포의 핵심이다.**

**비명 억제 — 숨 참기**

| 대응 | 비용 | 결과 |
|---|---|---|
| 숨 참기 (선딜레이 1초 안에 입력) | 숨 게이지 **3초** | 비명 발생 안 함 |
| 잠수 중 | 이미 게이지 소모 중 | 자동 억제(물속이라 비명 못 지름) |
| 게이지 3초 미만 | — | **억제 불가.** 비명 강제 발생 |
| 아무것도 안 함 | 없음 | 비명 발생(발생 9m / 1.0초) |

### 3.6 장시간 정지 시 자동 소리 (캠핑 방지) [신설]

목적은 숨는 플레이 제거가 아니라 **무기한 정지만 막는 것**이다.

| 항목 | 값 | 테스트 범위 |
|---|---|---|
| 발동 조건 | **20초 동안 누적 이동거리 3m 미만** | 15~25초 / 2~4m |
| 1단계 | 호흡음 — 발생 반경 **3m / 0.6초** | 2~4m |
| 증폭 | **15초마다 발생 반경 +2m** | 12~20초 |
| 최대 | **9m** | 8~12m |
| 초기화 | **5m 이상 이동 시 즉시** | 4~7m |
| SFX | 호흡 → 떨림 → 기침 | — |
| **적용** | **도망자 + 술래** | 고정 |
| 미적용 | 메아리 | 고정 |

**발동하지 않는 상태** — 타이머가 **정지(일시중단)**하며 파문이 발생하지 않는다. 초기화가 아니라 정지다.

| 상태 | 사유 |
|---|---|
| 밸브 상호작용 중 | 정지가 강제되는 행동. 이미 12m 파문을 내고 있다 |
| 잠수 중 | 물속 기침은 부자연스럽고, 이미 숨 게이지 압박을 받는다 |
| 설정 화면(F1) 등 메뉴 개방 중 | 플레이어가 조작 불가 |
| 낙하 복구 · 리스폰 등 이동 불가 연출 중 | 플레이어 의도와 무관 |

**미세 이동 악용 방지**: 판정은 순간 속도가 아니라 **20초 슬라이딩 윈도우의 누적 이동거리**다.
제자리 흔들기로는 3m를 채울 수 없어 타이머가 초기화되지 않는다.

**억제가 실제로 작동하는 근거 — 누적 총량이 아니라 탐지 거리와 좌표 고정**

| 상태 | 발생 반경 | 술래 탐지 거리(×1.2) | 발생 빈도 | 위치 |
|---|---|---|---|---|
| 걷는 도망자 | 2m | **2.4m** | 2m 이동마다 | 계속 이동 |
| 캠핑 1단계(20초) | 3m | **3.6m** | 15초마다 | **고정** |
| **캠핑 최대(65초~)** | **9m** | **10.8m** | 15초마다 | **고정** |

> **정지 상태는 누적 소음 총량으로는 순찰보다 조용하다**(호흡음은 15초에 1회뿐이라
> 6m마다 발소리를 내는 순찰을 총량으로 따라잡지 못한다). **그러나 65초 이후에는
> 탐지 거리가 10.8m까지 넓어지고 그 좌표가 고정되므로 발각 확률이 급격히 높아진다.**
> 20~35초의 짧은 매복은 탐지 거리가 3.6~6.0m에 그쳐 여전히 유효하며, 이는 의도된 여지다.

## 5. 사운드(SoundPulse) 시스템 — 핵심 메커니즘

이 게임에서 사운드는 곧 렌더러다. 시야를 만드는 유일한 수단이 소리이므로, 이 시스템이 사실상 게임의 전부다.

### 5.0 용어 정의 [신설]

세 개념을 반드시 구분한다. 구현에서 섞이면 방향 게이지가 청취 반경을 넘어서는 모순이 생긴다.

| 용어 | 정의 |
|---|---|
| **① 발생 반경** | SoundPulse가 생성되는 기본 범위. SoundType별 고정값 |
| **② 청취 반경** | 특정 역할이 인지 가능한 범위 = `발생 반경 × 재질 배율 × 역할 청취 배율 × 차폐 계수` |
| **③ 방향 표시 반경** | 인지한 소리에 방향 게이지가 나타나는 범위(3.4절) |

> **불변 조건: `방향 표시 반경 ≤ 청취 반경`**
> 방향 표시는 **인지한 소리에 대해서만** 나타나므로 청취 반경을 넘을 수 없다.

### 5.0-1 소음량 vs 노출 면적 — 두 지표를 통일하지 않는다 [신설]

파문의 "크기"를 나타내는 지표가 두 개이고 **서로 다른 것을 측정한다.**
같은 단어("노출량")로 부르면 문맥마다 공식이 달라 보여 혼란이 생기므로 용어를 분리한다.

| 용어 | 공식 | 쓰이는 곳 | 측정 대상 |
|---|---|---|---|
| **소음량** | 발생 반경 × 지속시간 **(선형)** | 무성 생존상 채점(8.2), 캠핑 누적 비교(3.6) | 채점·비교용 밸런스 지표 |
| **노출 면적** | 발생 반경² × 지속시간 **(제곱)** | 소리 등급 격차의 **설계 근거**(9.1) | 파문이 덮는 **면적 × 시간**(원 면적 πr²) |

> **두 지표는 서로 다른 것을 측정하므로 통일하지 않는다.**
> 노출 면적 기준 고함은 속삭임의 **126배**(1,210 vs 9.6),
> 소음량 기준으로는 **약 23배**(55 vs 2.4)다.

**어느 쪽이 옳은가는 문맥이 정한다.**

| 문맥 | 지표 | 이유 |
|---|---|---|
| 등급 격차 설계(9.1) | **노출 면적**(제곱) | 파문이 실제로 덮는 범위는 원 면적이라 제곱이 물리적으로 옳다. 선형으로 바꾸면 배율이 23배로 줄어 "실수 하나의 대가가 비선형적으로 크다"는 설계 논리가 무너진다 |
| 어워드 채점(8.2) | **소음량**(선형) | 제곱이면 고함 1회로 수상이 불가능해져 **정상 플레이를 처벌한다**. 채점은 상대 비교이므로 선형이 맞다 |

### 5.1 소리 등급 (Baseline)

아래 반경은 전부 **발생 반경**이다. 술래 청취 반경 = 발생 반경 × 1.2 (지속 × 1.5).

| 소리 | SoundType | 발생 반경 | 지속시간 | 술래 청취 반경 | 방향 표시 | 발생 조건 |
|---|---|---|---|---|---|---|
| 속삭임 | `Whisper` | 4m | 0.6초 | 4.8m | ✗ | 마이크 RMS -50~-30 dBFS |
| 대화 | `Conversation` | 9m | 1.2초 | **10.8m** | ✓ (10.8m) | 마이크 RMS -30~-15 dBFS |
| 고함 | **`Shout`** | 22m | 2.5초 | **26.4m** | ✓ (26.4m) | 마이크 RMS -15 dBFS 이상 |
| 걷기 | `Footstep` | 2m | 0.4초 | 2.4m | ✗ | 이동속도 ≤ 5.0m/s, **2m 이동마다**(5.1-1) |
| 질주 | `Sprint` | 6m | 0.8초 | 7.2m | ✗ | 이동속도 > 5.0m/s, **6m 이동마다**(5.1-1) |
| 밸브 회전 | `Valve` | 12m | 각 밸브 회전 시간(6.1) | 14.4m | ✗ | 밸브 상호작용 중 |
| **비명** | **`Scream`** | **9m** | **1.0초** | **10.8m** | ✓ (10.8m) | **술래 외침 공포 반경 22m 안, 억제 실패**(3.5) |
| 노크(메아리) | `Knock` | 9m | 1.2초 | **10.8m** | ✓ (10.8m) | 메아리 능력 사용 |
| **호흡음** | **`Breath`** | **3m → 9m** | **0.6초** | 3.6m → 10.8m | ✗ | **20초 정지 감지**(3.6) |

> **`Shout`(고함)과 `Scream`(비명)은 완전히 별개의 SoundType이다.** [신설]
> `Shout`은 **플레이어가 의도해서** 마이크로 내는 소리(22m·2.5초),
> `Scream`은 술래 외침에 의해 **강제로 발생**하는 캐릭터 자동 SFX(9m·1.0초)다.
> 어워드 판정(8절)에서 둘을 혼용하지 않는다.

**구분 불가 그룹 (의도적 설계)**

**대화 · 비명 · 노크**는 발생 반경 9m, 청취 반경 10.8m, 방향 표시가 모두 동일하다.
술래는 셋을 구분할 수 없다 — 이것이 메아리 심리전의 근간이다.
(지속시간 1.2 / 1.0 / 1.2초 차이는 실사용에서 식별 불가능한 수준으로 간주한다.)

### 5.1-1 발소리 파문의 발생 주기 [신설]

기존 문서는 걷기·질주 파문의 **발생 주기**를 정의하지 않았다. 그래서 ①이동 중 파문이
몇 번 생기는지 구현할 수 없고 ②무성 생존상의 소음량 합을 계산할 수 없었다.

**규칙: 발소리 파문은 "자신의 발생 반경과 같은 거리를 이동할 때마다" 1회 발생한다.**

| 소리 | 발생 반경 | 발생 간격 | 기준 속도 | 시간 간격 | 지속시간 | 결과 |
|---|---|---|---|---|---|---|
| 걷기 | 2m | **2m 이동마다** | 5.0 m/s | 0.40초 | 0.4초 | **끊김 없이 연속** |
| 질주 | 6m | **6m 이동마다** | 7.5 m/s | 0.80초 | 0.8초 | **끊김 없이 연속** |

**새로운 상수를 추가하지 않는다.** 발생 간격은 이미 있는 발생 반경 값을 재사용한 것이며,
그 결과 **발생 간격과 지속시간이 정확히 일치**해 이동 중 파문이 끊기지 않는다.

**시간이 아니라 이동거리 기준인 이유**
- 제자리 회전·미세 이동으로 파문을 양산하거나 회피할 수 없다(3.6 캠핑 방지와 정합)
- **1m당 소음량이 상수가 되어 무성 생존상이 계산 가능해진다**

**발생 간격에는 재질 배율을 적용하지 않는다.**

| 대상 | 재질 배율 |
|---|---|
| **발생 간격**(2m / 6m) | **미적용 — 항상 고정** |
| **발생 반경**(실제 들키는 범위) | **적용**(5.9절) |

간격이 재질마다 흔들리면 파문 점멸 리듬이 구역마다 달라져 혼란스럽고,
재질 효과가 소음량에서 상쇄되어 사라지기 때문이다.

### 5.2 음성 분류 파이프라인

```
1. 캡처   : Steamworks Voice API — 16kHz PCM, 20ms 프레임
2. 진폭   : 프레임별 RMS 산출 → dBFS 변환
3. 캘리브레이션 : 로비 입장 시 "가장 작은 목소리로 말해보세요" 3초 프롬프트
              → 개인별 baseline 측정 → 임계값에 개인 오프셋 적용
4. 대역 필터 : 80Hz~3,400Hz(인간 음성 주파수 대역)만 통과시키는 밴드패스 필터 적용
              → 팬 소음·키보드 타건음 등 저역/광대역 노이즈의 오분류 완화
5. 연속성 검사 : RMS가 임계값을 넘는 프레임이 최소 3프레임(60ms) 연속되어야 유효 발화로 인정
              → 순간적 임팩트 노이즈(마우스 클릭, 책상 두드림) 배제
6. 분류   : baseline 보정된 dBFS를 5.1 표의 3구간에 매핑
7. 디바운스 : 지속시간 0.15초 미만 발화는 무시(클릭·마찰음 오탐 방지)
8. 이벤트 생성 : SoundPulse(sourceId, position, radius, duration, type, timestamp)
```

> 캘리브레이션 없이 고정 임계값만 쓰면 마이크 감도 편차로 "속삭였는데 고함으로 분류"되는 사고가 빈발한다. 개인 baseline 보정은 MVP 필수 항목으로 승격한다. 대역 필터·연속성 검사는 캘리브레이션만으로 못 막는 환경 노이즈 오탐을 추가로 억제하기 위한 보강 단계다.

### 5.3 렌더링 이중화 (본인 vs 타인)

| 경로 | 지연 | 방식 |
|---|---|---|
| 본인 목소리 → 본인 화면 | 0ms | 로컬 마이크 진폭을 직접 셰이더 파라미터에 바인딩(네트워크 왕복 없음) |
| 본인 목소리 → 타인 화면 | 20~80ms | SoundPulse 이벤트 브로드캐스트 → 원격 클라이언트가 로컬 재현 |
| 환경음(걷기/밸브 등) | 20~80ms | 동일하게 이벤트 브로드캐스트 |

두 경로의 반경·지속시간·감쇠 곡선이 반드시 일치해야 한다. 불일치 시 "내가 보는 내 파문"과 "남이 보는 내 파문"이 달라져 눈치싸움의 공정성이 깨진다.

### 5.4 렌더링과 차폐(5.6)의 관계 — 이중 레이어 규칙

5.6에서 정의하는 차폐는 "탐지 가능 여부"(게임플레이 판정)이고, "화면에 무엇이 보이는가"(렌더링)는 아래처럼 별도의 이중 레이어로 확정한다.

| 레이어 | 판정 기준 | 표현 방식 |
|---|---|---|
| **판정 레이어**(필수) | 5.6 `ResolvePulseForListener`의 결과 | 서버가 "이 리스너는 이 이벤트를 알 수 있다"고 결론 내린 경우에만 이하 렌더링 진행 |
| **방향 힌트**(항상 표시) | 판정 레이어 통과 시 무조건 | 화면 가장자리 은은한 vignette로 발생 방향만 표시(정확한 위치 아님) — 벽 뒤에 있어도 "저쪽에서 뭔가 들렸다"는 정보만 제공 |
| **월드스페이스 링 이펙트**(조건부) | 방향 힌트 조건 + 카메라 Raycast로 실제 시야가 확보된 경우만 | 실제 3D 공간에 링이 그려짐 — 벽 뒤에서 난 소리는 "들렸다는 느낌"만 주고, 실제로 그 지점이 보이는 위치(모퉁이를 돈 뒤 등)에 도달해야 시각적으로 링이 나타난다 |

> 이 이중 레이어 덕분에 "벽 너머 소리가 났는데 마치 벽이 투명한 것처럼 링이 그려지는" 부자연스러움을 방지하면서도, 0~80ms 즉각 피드백 원칙(2.1)은 방향 힌트 레이어로 그대로 유지된다.

### 5.5 데이터 구조 (의사코드)

```csharp
// 이 구조체는 발생원(source) 기준 물리값만 담는다.
// 리스너별 인지 배율(5.7)과 차폐 감쇠(5.6)는 서버가 리스너마다 별도로 계산하며,
// 클라이언트에는 계산이 끝난 perceivedRadius/perceivedDuration만 전달된다.
struct SoundPulse {
    ulong   sourcePlayerId;
    Vector3 position;
    float   radius;       // m, 발생원 기준 원본값
    float   duration;     // s, 발생원 기준 원본값
    SoundType type;        // Whisper, Talk, Shout, Walk, Sprint, Valve, Knock
    float   timestamp;     // 서버 기준 시각
}

enum SoundType { Whisper, Talk, Shout, Walk, Sprint, Valve, Knock }

// 리스너에게 실제 전달되는 값 (서버 계산 결과, 5.6/5.7 참조)
struct PerceivedPulse {
    float   perceivedRadius;
    float   perceivedDuration;
    Vector3 sourcePos;
    bool    worldSpaceRingVisible; // 5.4 카메라 LOS 체크 결과
}
```

### 5.6 사운드 차폐(Occlusion) 규칙 — 핵심 확정 사항

5.1의 반경 수치는 "빈 공간 기준 최대값"이다. 실제 전파는 지형에 의해 감쇠된다. 이 규칙이 없으면 10·11절의 "은신처"·"파문 차단막" 설계가 기계적으로 무의미해지므로 최우선으로 명시한다.

**판정 알고리즘 (서버 권위, 리스너별 개별 계산)**

```
function ResolvePulseForListener(pulse, listener):
    straightDist = Distance(pulse.position, listener.position)

    # 1) 역할별 인지 배율 적용 (5.7) — 술래는 여기서 먼저 확장된 반경을 갖는다
    baseRadius = pulse.radius * RoleRadiusMultiplier(listener.role)
    baseDuration = pulse.duration * RoleDurationMultiplier(listener.role)

    # 2) 1차 컷: 배율 적용 후에도 물리적으로 닿지 않으면 즉시 스킵 (대역폭 절약)
    if straightDist > baseRadius:
        return null  # 이 리스너에게는 이벤트 자체를 전송하지 않음

    # 3) 차폐 레이캐스트: pulse.position → listener.position 사이 SoundBlocking 레이어 검사
    hits = Physics.LinecastAll(pulse.position, listener.position, layer="SoundBlocking")

    if hits contains tag "HardBlocker":       # 무대 커튼 등 (11.1)
        return null                            # 완전 차단, 이벤트 미전송
    else:
        wallCount = hits.count                 # 일반 벽/문 개수
        attenuation = 0.5 ^ wallCount          # 벽 1개당 반경 50%씩 감쇠
        perceivedRadius = baseRadius * attenuation
        perceivedDuration = baseDuration * max(attenuation, 0.5)  # 지속시간은 최대 50%까지만 깎임

        if straightDist > perceivedRadius:
            return null
        return PerceivedPulse(perceivedRadius, perceivedDuration, pulse.position)
```

**지형지물별 차폐 태그 매핑**

| 지형지물 | 태그 | 효과 |
|---|---|---|
| 일반 벽(기본 지오메트리) | `Wall` | 통과 시 반경 ×0.5 (중첩 가능, 벽 2개면 ×0.25) |
| 락커(10.1 은신처) | `Wall`(얇은 오브젝트 취급) | 동일 규칙, 콜라이더는 락커 사이 틈만 노출되도록 배치해 시각적 은신 연출과 일치시킴 |
| 무대 커튼(11.1) | `HardBlocker` | 완전 차단(이벤트 자체 미전송) — 유일한 절대 차단 지형지물 |
| 문(닫힘 상태, v1.x) | `Wall` | 열림 상태는 차폐 없음(콜라이더 비활성) |
| 수면 아래(잠수) | 해당 없음 | 애초에 파문 미발생(5.5절 재질 표), 이 규칙과 무관 |

> **성능 고려(15.5 연계)**: 리스너별 레이캐스트 비용은 `초당 파문 발생 수 × 접속 인원 수`에 비례한다. 6인 기준 초당 파문 2~4개 × 리스너 5명 ≈ 초당 10~20회 레이캐스트로, `Physics.Linecast`가 충분히 감당 가능한 수준이다. `SoundBlocking` 레이어는 렌더 메시와 분리된 전용 콜라이더 레이어로 둬서 다른 물리 연산(플레이어 이동 충돌 등)과 섞이지 않게 한다.

### 5.7 리스너별 인지 배율 적용 방식

**인지 배율은 연출이 아니라 실제 탐지 판정에 반영되는 기능적 수치다.** 같은 소리라도 술래는 실제로 더 멀리, 더 오래 감지한다(2.1의 핵심 3대 시스템 중 하나로 명시된 것과 일치).

```
[Source] --물리적 이벤트(5.1의 원본 반경/지속)--> [Server]
    │
    ├─ Listener A(Runner) : radius × 1.0, duration × 1.0  → 5.6 차폐 계산 → 전송 여부 결정
    ├─ Listener B(Seeker) : radius × 1.2, duration × 1.5  → 5.6 차폐 계산 → 전송 여부 결정
    └─ Listener C(Echo)   : radius × 1.0, duration × 1.0  → (관전 목적, 정보 참고용 동일 적용)
```

`SoundPulse` 구조체(5.5)는 발생원 기준 반경/지속만 담는다. 리스너별 배율·차폐 적용은 서버가 매번 계산하며, 클라이언트로는 계산이 끝난 `PerceivedPulse`만 내려간다. 클라이언트는 받은 값을 그대로 렌더링 크기·지속시간에 사용하고 추가 배율 연산을 하지 않는다 — 이렇게 해야 5.3의 "내가 보는 내 파문 vs 남이 보는 내 파문 일치 원칙"이 역할별 배율과 충돌하지 않는다.

### 5.8 음성 입력 방식 및 오탐 방지

**기본 방식: Voice Activity Detection(VAD) 오픈마이크 + 수동 강제 뮤트.**

- PTT(누르고 말하기)를 기본값으로 채택하지 않는다. 이유: 핵심 훅("말해야 보인다")은 무의식적으로 말이 새어나가는 순간의 공포가 핵심이므로, 버튼을 눌러야만 소리가 나는 PTT는 이 훅을 구조적으로 무력화한다.
- 실생활 인터럽트(전화, 다른 사람과의 대화 등) 대응을 위해 **Left Alt 홀드 = 강제 마이크 뮤트** 키를 항상 제공한다. 이 키를 누르는 동안은 어떤 소리도 SoundPulse로 변환되지 않는다.
- 오탐 방지는 5.2 파이프라인의 대역 필터(4단계)·연속성 검사(5단계)로 처리한다.
- 설정 화면(12.6)의 "게임플레이" 탭에서 "발화 방식: VAD(기본) / PTT(대체)" 토글을 제공한다. PTT 선택 시 "게임 핵심 긴장감이 줄어든다"는 안내 문구를 노출한다.

**발생 반경**에 곱한다(발생 간격에는 적용하지 않는다 — 5.1-1).

### 5.9-1 숨 게이지 — 통합 상태 전이 규칙 [갱신]

|---|---|
| 잠수 유지 | **초당 -1**(연속) |
| 비명 억제 | **-3**(즉시, 1회성) |

**회복 (단일 규칙)**

```
회복 조건: 상태 ≠ 잠수  AND  회복 대기 플래그 = false (마지막 소모 후 2초 경과)

회복 속도:
  상태 = 수면   → 초당 +2
  상태 = 물 밖  → 초당 +4
```

최대 8초에서 상한. 회복 중 다시 잠수하면 즉시 중단되고 초당 -1로 전환된다
(회복 대기 플래그도 2초로 리셋).

> **[갱신] 기존 "물 밖으로 완전히 나가면 즉시 100% 회복" 규칙은 삭제한다.**
> 이 규칙은 두 가지 악용을 만들었다 —
> ① 육상에서는 비명 억제 비용이 0이 되어 게이지 제약이 사라지고,
> ② 잠수 → 물 밖 → 재잠수 반복으로 게이지가 사실상 무제한이 된다.
> **물 밖 초당 +4**가 "물 밖에서는 빠르게 회복"이라는 원래 의도를 유지하면서 두 악용을 모두 차단한다.

**상태별 소요 시간 (계산 검증)**

| 상황 | 소모 | 대기 | 회복 | 총 |
|---|---|---|---|---|
| 육상 비명 억제 1회 | -3 | 2초 | 0.75초 | **2.75초** |
| 수면에서 비명 억제 1회 | -3 | 2초 | 1.5초 | **3.5초** |
| 7초 잠수 후 물 밖 | -7 | 2초 | 1.75초 | **3.75초** |
| 전체 고갈(8초) 후 물 밖 | -8 | 2초 | 2.0초 | **4.0초** |

**고갈 시 (질식 페널티)**: 잠수 중 게이지가 0이 되면 **강제 부상 + 이동속도 -20% 3초 +
고함급(발생 반경 22m) 파문 1회 강제 발생**(기침·헐떡임 연출).

**연속 억제 최대 2회** — 게이지 8초 ÷ 억제 3초. 다만 외침 쿨다운이 45초라
**외침만으로는 이 한계가 발동하지 않는다**(45초면 어떤 상태에서든 만충). 이 제약이
실제로 작동하는 것은 **잠수와 겹칠 때뿐**이며, 그것이 이 시스템의 의도된 긴장이다.

| 상황 | 결과 |
|---|---|
| 육상에서 외침을 45초마다 맞음 | 항상 억제 가능. 제약 없음 |
| 5초 잠수(-5, 잔여 3) 직후 외침 | 억제 가능하나 게이지 0 |
| 6초 잠수(-6, 잔여 2) 직후 외침 | **억제 불가 → 비명 강제 발생** |

## 6. 밸브 · 탈출 시스템

### 6.1 밸브 상태기계

```
[Closed] --interact(hold)--> [Rotating(밸브별 회전시간, 소음 12m 발생)] --완료--> [Open]
   ▲                               │
   └───────interrupt(이탈)─────────┘   (진행도 초기화, 완료 전 이탈 시 리셋)
```

- 밸브 회전 중 소음(발생 12m, 회전 시간 내내)이 지속 발생 — 중간에 멈춰도 이미 발생한 소음은 취소되지 않음
- 완료 전 상호작용 취소 시 진행도는 0으로 리셋(부분 진행 저장 없음, MVP 단순화)
- 밸브 3개 모두 `Open` → **양쪽 출구 게이트 `Open`** → 탈출 가능(10.5절)

**밸브별 회전 시간 차등 [갱신]**

**미니게임을 추가하지 않는다.** 차이는 회전 시간과 환경 규칙으로만 만든다.

| 밸브 | 위치(10절) | 회전 | 환경 규칙 | 위험 |
|---|---|---|---|---|
| **A** | 기계실 | **3.0초** | 기계 앰비언스로 밸브 소음 **×0.5**(발생 12m→6m) | **퇴로 없음**(출입구 1개) |
| **B** | 메인 풀 깊은쪽 3.5m | **2.0초** | **수중.** 잠수 필수, 물속 관측 불가 | **한 숨에 완료** |
| **C** | 물탱크실(2층) | **4.0초** | 금속 계단 ×1.5. 계단 2개 | **이동 비용** |

#### 6.1-1 밸브 B 정밀 명세 [신설]

**타임라인 (숨 게이지 8초 기준)**

| 단계 | 소요 | 게이지 소모 | 완료 시점 | 잔여 |
|---|---|---|---|---|
| 진입(하강) | 1.0초 | **-1.0** | t=1.0 | 7.0 |
| 회전 | 2.0초 | **-2.0** | t=3.0 | 5.0 |
| 부상(상승) | 1.0초 | **-1.0** | t=4.0 | **4.0** |

**총 4.0초 소요, 게이지 4.0초 잔여(정확히 50% 사용).**
세 단계 모두 머리가 수면 아래이므로 **전 구간에서 초당 -1이 적용된다.**

**실패 처리**: 회전 완료 전 부상하면 **밸브 진행도 리셋**. 게이지 0 도달 시 질식 페널티(5.9-1).

**게이지 0초 경계 처리 (판정 우선순위)**

`t = 8.0초`처럼 **부상 완료와 게이지 고갈이 같은 시점에 성립**하는 경우:

| 순위 | 판정 | 처리 |
|---|---|---|
| **1** | **부상 완료** | 성립하면 **밸브 B 성공으로 확정** |
| **2** | 게이지 고갈(질식) | 순위 1이 이미 성공 확정된 경우 **무시한다** |

> **정확히 게이지 0초에 부상이 완료되면 도망자는 성공한다.**
> 부상 완료 판정이 질식 판정보다 항상 우선한다.

**잠수 피드백 — 상시 표시 + 2단계 경고**

정상 수행(4.0초)은 경고가 뜨기 전에 끝나므로, 정보는 **상시 표시**로 주고
**경고**는 지체했을 때만 켜지도록 분리한다. 새 게이지·새 시스템을 추가하지 않는다.

| 구분 | 내용 |
|---|---|
| **상시 표시** | ①숨 게이지 바의 **1.0초 지점 귀환 한계선 마커** ②밸브 회전 **원형 진행 게이지** ③잔여 게이지 수치 |
| **1단계 — 주의** | **상태 = 잠수** AND 잔여 ≤ **3.0초** → 게이지 바 황색 + 느린 심박음 |
| **2단계 — 위험** | **상태 = 잠수** AND 잔여 ≤ **1.0초**(귀환 한계선 도달) → 적색 + 빠른 심박음 + 화면 가장자리 vignette |

> **발동 전제: 현재 상태가 `잠수`일 때만 평가한다.** 숨 게이지는 비명 억제와 공유하는
> 자원이므로, 이 조건이 없으면 육상에서 억제 2회(-6, 잔여 2초) 시에도 익사 경고가 뜬다.
> 상태가 잠수에서 벗어나면 경고는 **즉시 해제**된다(잔여량 무관). 귀환 한계선 마커도 잠수 중에만 표시한다.

**네트워크**: 밸브 진행도는 **서버 권위**로 관리하며 클라이언트는 예측 표시만 한다.
여유 4.0초는 왕복 지연 200ms 기준 20배 마진이라 지연으로 성공이 불가능해지지 않는다.

### 6.3 승패 판정 (의사코드) [갱신]

**도망자의 최종 상태 3종**

| 상태 | 정의 |
|---|---|
| **탈출** | 밸브 3개 개방 후 출구 접촉 |
| **태그** | 술래에게 태그당함(메아리 전환) |
| **미탈출** | 시간 종료 시점에 살아 있으나 탈출하지 못함 |

```csharp
// [라운드 종료 시점에 1회만 평가]
if (valvesOpened == totalValves && escaped > (tagged + notEscaped))
    result = Result.RunnersWin;
else
    result = Result.SeekerWin;
```

> **이 판정식의 성격**: 기존 `탈출 > 태그`의 **시간 종료 상태를 명확히 처리하기 위한 보완**이다.
> **"완전히 동일하다"고 말할 수 없다.** 보완이 적용되는 조건은 `미탈출 > 0`,
> 즉 **시간 종료 시점에만** 발생한다.

| 상황 | 기존식 `탈출>태그` | 보완식 `탈출>(태그+미탈출)` | 차이 |
|---|---|---|---|
| 모든 도망자가 탈출/태그로 확정(미탈출=0) | 동일 | 동일 | **없음** |
| **시간 종료 · 탈출1 · 태그0 · 미탈출2** | **도망자 승** | **술래 승** | **★ 여기서만 다름** |

기존식은 "탈출 1명 / 태그 0명"을 도망자 승리로 판정했으나, 남은 2명이 목표를
달성하지 못했음에도 승리가 되어 **HUD의 "탈출 2명" 표현과 어긋났다.**
미탈출 생존자를 목표 미달로 집계함으로써 이 불일치를 제거한다.

**3 Runner 전수검증** — 10/10 전부 "탈출 2명 이상"과 일치한다.

| 탈출 | 태그 | 미탈출 | 판정 | 탈출≥2 |
|---:|---:|---:|---|---|
| 3 | 0 | 0 | 도망자 승 | ✓ |
| 2 | 1 | 0 | 도망자 승 | ✓ |
| 2 | 0 | 1 | 도망자 승 | ✓ |
| 1 | 2 | 0 | 술래 승 | ✗ |
| 1 | 1 | 1 | 술래 승 | ✗ |
| 1 | 0 | 2 | 술래 승 | ✗ |
| 0 | 3 | 0 | 술래 승 | ✗ |
| 0 | 2 | 1 | 술래 승 | ✗ |
| 0 | 1 | 2 | 술래 승 | ✗ |
| 0 | 0 | 3 | 술래 승 | ✗ |

**라운드 종료 조건**

| 조건 | 처리 |
|---|---|
| 모든 도망자가 탈출 또는 태그로 확정 | 미탈출=0으로 평가 |
| **태그 2명 도달** | 남은 도망자 1명 → 탈출 최대 1 < 2 → **즉시 술래 승리 확정, 라운드 종료** |
| 제한시간 종료 | 생존·미탈출자를 미탈출로 집계 후 평가 |

> **술래는 도망자 3명을 전부 태그할 필요가 없다. 2명이면 확정이다.**
> 문서 어디에서도 "살아있는 도망자 전원 태그"라고 서술하지 않는다.

**동일 프레임 처리 우선순위 [신설]**

| 순위 | 이벤트 | 처리 |
|---|---|---|
| **1** | **탈출 확정** | 출구 접촉이 성립한 도망자를 먼저 탈출로 확정 |
| **2** | **태그 확정** | 남은 도망자에 대해 태그 판정 적용 |
| **3** | **제한시간 종료** | 위 둘을 반영한 뒤 잔여 생존자를 미탈출로 집계 |
| **4** | **승리 판정** | 판정식 1회 평가 |

| 경계 상황 | 처리 |
|---|---|
| 밸브 미완료 + 시간 종료 | 밸브 조건 불충족 → 탈출 인원과 무관하게 **술래 승리** |
| 시간 종료와 탈출이 동일 프레임 | **탈출을 먼저 확정**(순위 1) — 도망자에게 유리하게 해석 |
| 탈출과 태그가 동일 프레임(같은 도망자) | **탈출 우선.** 출구에 닿았다면 탈출로 확정 |
| 태그 2명과 탈출이 동일 프레임 | 탈출 먼저 확정 → 태그 확정 → 태그 2명이면 종료(탈출1·태그2 = 술래 승) |

**서버 권위**: 모든 판정은 서버에서만 수행한다. 클라이언트 예측은 표시용이며 판정에 관여하지 않는다.

목표: 술래 승률 40~60% 구간. MVP 플레이테스트에서 이 구간을 벗어나면 9절 수치부터 조정한다.

### 6.4 밸브 상호작용 중 연결 끊김 처리

| 상황 | 처리 |
|---|---|
| 밸브 회전 중 상호작용자 연결 끊김 | 진행도 즉시 0으로 리셋(6.1 "완료 전 이탈" 규칙과 동일하게 취급) |

- 결과 화면 전환 즉시 어워드 3종 판정(아래 8.1~8.3)
- 리매치 투표: 15초 카운트다운, 과반 찬성 시 즉시 재시작(역할 재추첨)

### 8.1 최다 비명상 [갱신]

```
최다 비명상 = 세션 내 SoundType.Scream 이벤트 발생 횟수가 가장 많은 도망자
```

| 규칙 | 내용 |
|---|---|
| 집계 대상 | **`SoundType.Scream` 이벤트만** |
| **`Shout` 제외** | **고함 횟수는 판정에 일절 반영하지 않는다** |
| 억제 성공 시 | 숨 참기로 비명이 **발생하지 않았다면 집계하지 않는다**(이벤트 자체가 없음) |
| 공포 반경 밖 | 22m 밖은 비명이 발생하지 않으므로 집계 대상 없음 |
| 청취 여부 무관 | 술래가 10.8m 밖이라 **듣지 못했어도 비명 이벤트는 발생했으므로 집계한다** |
| 메아리 | **대상 아님**(메아리는 비명을 내지 않는다) |
| 동점 | 동점자 전원 공동 수상 |

> **[갱신] 기존 기준 "세션 로그의 `SoundType.Shout` 발생 횟수"는 잘못이었다.**
> `Shout`(고함)은 플레이어가 의도해서 내는 소리이고, 비명은 술래 외침에 의해
> 강제로 발생하는 **`Scream`**이다(5.1절). 집계 기준은 "술래가 인지했는가"가 아니라
> **"비명 이벤트가 발생했는가"**다.

### 8.2 무성 생존상 [갱신]

```
파문 소음량(1회) = 발생 반경 × 지속시간        ← 제곱이 아니라 선형
무성 점수 = Σ(본인이 발생시킨 파문 소음량) ÷ 총 이동거리(m)
           단, 밸브 회전음은 합계에서 제외
→ 생존자 중 무성 점수가 가장 낮은 플레이어 수상
```

| 규칙 | 내용 |
|---|---|
| 발생 반경 | **재질 배율 적용 후**의 값 사용(타일 걷기 = 2 × 1.3 = 2.6m) |
| 중복 집계 금지 | 한 파문이 여러 명에게 들려도 **1회만** 계산. 청취자 수 무관 |
| 본인 발생분만 | 자신이 직접 발생시킨 파문만 자기 점수에 반영 |
| 생존 요건 | **탈출 또는 미탈출**만 수상 대상. 태그당한 메아리는 제외 |
| 0 나누기 방어 | 총 이동거리 **1m 미만이면 수상 대상 제외** |
| **밸브 제외** | **목표 수행을 처벌하지 않기 위해 밸브 회전음은 계산에서 뺀다** |

> **[갱신] 기존 기준 "이동거리 대비 파문 발생 0회 여부"는 사실상 달성 불가능했다**
> (움직이면 반드시 발소리가 난다 — 5.6절). 또 제곱 공식은 **밸브 수행자를 처벌**하고
> 고함 1회로 수상이 불가능해지는 결함이 있었다. **제곱 → 선형 + 밸브 제외**의 최소 수정으로
> 두 결함을 모두 해소했으며 **새 상수는 0개**다.

### 8.3 최고의 거짓말상 — 인과관계 판정 [갱신]

> **판정의 성격**: 이 규칙은 실제 인과관계를 수학적으로 증명하는 것이 아니라,
> **노크에 의해 술래가 유인되었다고 간주할 수 있는 최소 조건을 충족하면 성공으로
> 판정하는 휴리스틱 규칙**이다.

```
d(t) = 술래와 Knock 위치 사이의 거리

[감시 개시 조건]  Knock 발생 시점 t0에서
  ① d(t0) > 9m                     ← 아니면 감시를 시작하지 않는다
  ② d(t0) >= d(t0 - 2초)            ← 직전 2초간 접근 중이 아니었을 것

[감시]  t0부터 30초간 0.5초 간격 샘플링
  ③ 접근누적 += 0.5초   (직전 샘플보다 거리가 줄었을 때만)
  ④ d <= 9m 도달 시점에 접근누적 >= 3.0초  →  유인 성공

[감시 종료 — 전부 실패 처리]
  30초 경과 / 술래가 도망자를 태그 / 라운드 종료
```

**사용하는 데이터는 거리·시간뿐이다.** 이동 벡터·시야·경로 분석을 쓰지 않는다.

| 상수 | 값 | 역할 |
|---|---|---|
| 진입 판정 거리 | **9m** | 노크 발생 반경과 동일(3.2절) |
| 감시 시간 | **30초** | 기존 값 유지 |
| 사전 판정 창 | **2초** | ②의 "접근 중이 아니었음" 확인 구간 |
| 샘플 간격 | **0.5초** | 네트워크 위치 갱신에 충분 |
| 접근누적 하한 | **3.0초** | 스쳐 지나감과 실제 유인을 가르는 임계값 |

| # | 상황 | 판정 |
|---|---|---|
| 1 | 우연히 지나감 | **실패**(접근누적 3.0초 미달) |
| 2 | 이미 그쪽으로 이동 중이었음 | **실패**(②가 불만족 — 유인이 아니다) |
| 3 | Knock 직후 반대로 갔다가 복귀 | **성공**(복귀 구간에서 조건 충족 시) |
| 4 | 짧은 시간에 여러 Knock | **1회만** — 진입 시 가장 최근 성공 건 1개만 집계 |
| 5 | 같은 위치에서 반복 Knock | **1회만** — 동일 위치 활성 감시는 최신 1개로 갱신 |
| 6 | Knock 후 술래가 태그 | **실패**(감시 즉시 종료) |
| 7 | Knock 후 아무도 접근 안 함 | **실패**(30초 경과) |
| 8 | Knock 시점에 이미 9m 이내 | **실패**(①이 불만족 — 감시를 시작조차 하지 않는다) |

**대상**: 메아리 전용. 도망자·술래는 이 어워드의 대상이 아니다.

> **Knock 자체의 규칙은 전혀 변경하지 않았다**(3.2절 그대로). 어워드는 Knock 이벤트를 **읽기만** 한다.

## 9. 밸런스 설계 근거 (수치 산출 로직)

이 절은 5·6절의 숫자가 "왜 이 값인가"를 설명한다. 모두 baseline이며 M3(MVP) 플레이테스트에서 검증·조정 대상이다.

### 9.1 소리 반경 스케일링 — 왜 4m / 9m / 22m인가

- 반경 비율: 속삭임:대화:고함 = 1 : 2.25 : 5.5
- "대화"까지는 협업에 필요한 최소 비용으로 느끼게 하고, "고함"부터는 명백한 실책으로 체감되도록 격차를 크게 벌린다.
- **노출 면적**(발생 반경² × 지속시간, 즉 파문이 덮는 면적 × 시간)을 기준으로 계산하면 고함은 속삭임 대비 약 **126배**(1,210 vs 9.6 — 면적 30.25배 × 지속시간 4.17배)에 달한다. 실수 하나의 대가가 명확히 느껴지도록 의도한 비선형 설계다.
- **여기서 제곱을 쓰는 이유**: 파문이 실제로 덮는 범위는 원 면적(πr²)이므로 등급 격차를 설명할 때는 제곱이 물리적으로 옳다. 반면 8.2 무성 생존상은 **채점 지표**라 선형(소음량)을 쓴다 — **두 지표는 서로 다른 것을 측정하므로 통일하지 않는다**(5.0-1절).

### 9.2 술래 이속 보정 — 왜 4인 기준 +8%인가

- 도망자 기본속도 5.0m/s, 술래 5.4m/s(+8%) → 상대속도 0.4m/s
- 술래가 도망자를 20~25m 거리에서 발견했다고 가정하면, 상대속도만으로 좁혀지는 데 약 **50~62초** 소요
- 한 판 8~12분 중 추격 국면이 과도하게 길어지지 않으면서도, 도망자가 지형지물과 파문 재생성 텀(0.6~2.5초)을 활용해 따돌릴 여지를 남기는 균형점

### 9.3 밸브 회전 시간 / 소음 12m — 왜 이 조합인가 [갱신]

- **기준은 밸브 A(3.0초)다.** 12m 반경 소음이 회전 내내 지속 → 술래가 그 반경 안에 있다면 도착 시간(12m ÷ 5.4m/s ≈ 2.2초)이 회전 완료 시점(3.0초)과 겹쳐, 인터셉트가 유의미한 확률로 발생
- **밸브 B(2.0초)는 인터셉트 창이 좁은 대신 잠수 자원을 요구하고, C(4.0초)는 창이 넓은 대신 2층 이동 비용을 요구한다** — 같은 12m 소음에 서로 다른 리스크를 붙인 것이 밸브 차등화의 근거다(6.1절)
- 즉 밸브 작업은 "안전한 루틴"이 아니라 매번 "술래를 부를지 말지"를 재는 도박으로 설계됨(15.5절 성능·9절 밸런스 원칙과 직결)

### 9.4 인원별 밸브 수·이속 보정 조정 로직

- 밸브 수를 3개로 고정한 이유: 도망자가 늘어도(3~5인) 병렬 작업 상한을 3으로 묶어, 인원이 많을수록 클리어가 과도하게 쉬워지는 것을 방지
- 대신 인원이 늘수록 술래 이속을 +5%→+12%로 단계적으로 높여 난이도를 유지
- 6인 구간에서 회전시간을 3초→3.75초(+25%)로 늘린 것은, 늘어난 인력이 밸브 작업 병목을 지나치게 빨리 해소하는 것을 상쇄하는 보정

### 9.5 목표 승률 40~60%의 의미

- 어느 한쪽이 상시 우세하면 "술래 하기 싫어서" 로테이션 동기가 무너지고, 파티게임 특유의 반복 재플레이가 죽는다
- 튜닝 우선순위: ① 술래 이속 보정 → ② 밸브 회전시간 → ③ 밸브 반경/소리 등급 → ④ 맵 지형(마지막 수단, 재작업 비용 큼)

## 10. 맵 설계 — 심야 실내수영장 (MVP 대상)

**[갱신] 45×35m 단층 8구역 → 52×40m L자형 2층 13구역으로 전면 교체한다.**

| 항목 | 값 |
|---|---|
| 크기 | **52m × 40m** (L자형) |
| 층수 | **2층** (지상 + 관람층 Y +3.5m) |
| 구역 수 | **13개** |
| 대각선 | 약 65.6m |

고함(발생 22m / 청취 26.4m)은 맵 전체를 덮지 못한다 — 의도된 설계.

### 10.1 구역 구성표 [갱신]

### 10.2 밸브 배치와 이동 거리 [갱신]

| 밸브 | 위치 | 회전(6.1) | 위험 |
|---|---|---|---|
| **A** | 기계실(막다른 방) | 3.0초 | 퇴로 없음 |
| **B** | 메인 풀 깊은쪽 3.5m(**수중**) | 2.0초 | 한 숨에 완료 |
| **C** | 물탱크실(**2층**) | 4.0초 | 이동 비용 |

| 구간 | 거리 | 도망자 걷기 | 도망자 질주 | 술래 |
|---|---|---|---|---|
| A ↔ B | 34m | 6.8초 | 4.5초 | 6.3초 |
| B ↔ C | 32m | 6.4초 | 4.3초 | 5.9초 |
| A ↔ C | 44m | 8.8초 | 5.9초 | 8.1초 |

스프린트 1회 사거리 = 7.5 m/s × 5초 = **37.5m**
→ A↔B(34m)·B↔C(32m)는 1회로 도달 가능, **A↔C(44m)는 불가능**.

### 10.3 순환로 [신설]

| 경로 | 길이 |
|---|---|
| L1 대순환 | 약 96m |
| L2 서편 소순환 | 약 44m |
| L3 수직 순환 | 약 52m |
| L4 서비스 순환 | 약 20m |

스태미나 5초(37.5m) 기준 L2(44m)는 거의 한 바퀴, L1(96m)은 3회 분할이 필요하다.

### 10.4 설계 의도

- 밸브 3개가 각각 **막다른 방(기계실)** · **수중(메인 풀)** · **2층(물탱크실)** 에 배치되어, 밸브마다 완전히 다른 종류의 리스크를 안게 설계됨
- 메인 풀 홀은 모든 구역을 잇는 허브이자 유일한 "안전 은폐 자원"(수면)을 가진 공간 — 자연스럽게 교전이 집중되는 지점
- 라이프가드실의 유리창은 청각 정보(파문)를 시각 정보로 보조하는 유일한 지형지물 — 향후 뮤테이터/난이도 조절 지렛대로 활용 가능
- 락커·벽 등 구역 경계는 전부 5.6절 `Wall` 태그가 적용되어, 인접 구역으로 소리가 그대로 새지 않고 통과당 반경이 절반씩 줄어든다
- **재질이 동선 선택 자체를 밸런싱한다** — 직원 통로(금속 ×1.5)는 빠르지만 시끄럽고, 로비·라커룸(카펫 ×0.7)은 조용하지만 예측되기 쉽다

### 10.5 출구 배치 [갱신 — 1개 → 2개]

| 출구 | 위치 | 접근 |
|---|---|---|
| **출구 1 — 배수로** | 남동, 직원 통로 끝 | 금속 통로(×1.5) 경유 필수 — 시끄러움 |
| **출구 2 — 정문** | 북서, 로비 옆 | 카펫(×0.7) 경유 — 조용하지만 예측 쉬움 |

두 출구 직선거리 **약 52m**. 술래 이동 시간 **9.6초** — **한쪽만 지킬 수 있다.**
밸브 3개 완료 시 **양쪽 출구에서 고함급(발생 22m) 개방음**이 발생한다.

### 10.6 플레이 동선 예시 (내부 검증용 시나리오)

1. 도망자 3인, 로비 스폰 직후 각자 라커룸/풀 홀/관람층으로 분산 정찰(은신 페이즈)
2. 한 명이 기계실로 진입해 밸브 A 회전 시작 → 12m 반경 소음 발생(단 기계 앰비언스로 ×0.5 → 6m)
3. 술래가 메인 풀 홀에서 소음을 인지, 기계실로 이동
4. 다른 도망자가 2층 물탱크실에서 밸브 C 작업 개시 — 금속 계단(×1.5)이 이동을 광고한다
5. 세 번째 도망자가 수중 밸브 B에 도전 — 숨 게이지 4.0초를 소모하고 부상
6. 태그 발생 시 해당 도망자 메아리로 전환, 20초 잠금 후 노크(라운드당 5회)로 유인 개시

## 11. 맵 설계 — 폐극장 (v1.0 콘텐츠)

전체 플레이 구역 약 40m × 30m. 그레이박스+미감 3주 규모.

### 11.1 구역 구성표

| 구역 | 규모(대략) | 핵심 기능 | 사운드 특성 | 연결 구역 |
|---|---|---|---|---|
| 로비 | 8×6m | 스폰 지점 | 표준 | 객석 |
| 객석 | 18×16m | 대형 개방구역, 좌석 열이 은신+시야 차단 하드커버 | 표준 | 로비, 무대, 조명실 계단 |
| 무대 | 14×10m | 대형 커튼 = **파문 차단막**(5.6 `HardBlocker` 태그, 유일한 완전 차단 지형지물) | 표준 | 객석, 분장실 A/B, 소품보관실 |
| 분장실 A/B | 각 5×5m | 거울·소품 은신처 | 표준 | 무대 |
| 소품보관실 | 6×6m | **밸브 #1** | 표준(소품 충돌 SFX 존재) | 무대 |
| 조명실/그리드 | 수직 구조, 좁은 통로+사다리 | **밸브 #2**, 진입로 1개뿐(고립 리스크) | 표준 | 객석 계단(단일 연결) |
| 무대 아래 지하통로 | 협소, 나무 바닥 | **밸브 #3** | **삐걱대는 마루 — 이동 시 강제 "걷기" 소리 발생, 은신 불가**(하이리스크·하이리워드 지역) | 무대, 비상구 |
| 비상구 | 4×5m | 탈출 지점 | 표준 | 지하통로 |

### 11.2 설계 의도

- 커튼(파문 차단막)은 심야 수영장에 없던 신규 지형지물 — 소리를 물리적으로 완전 차단할 수 있는 유일한 사례(5.6절 `HardBlocker`)로, "숨는다"의 정의를 확장
- 조명실/그리드는 진입로가 하나뿐이라 밸브 작업 중 퇴로가 없음 — 6.1 밸브 시스템의 리스크를 극단화한 배치
- 지하통로는 은신이 원천 봉쇄된 구간으로 설계해, 같은 밸브 메커니즘이라도 맵마다 완전히 다른 텐션을 만들도록 함(맵 1~2개로 반복 소비 가능하게 하는 장치)

## 13. 멀티플레이 세션 설계

### 13.1 세션 흐름

```
방 생성(호스트) → 방코드/오버레이 초대 → 로비 → 역할 추첨 연출(3초)
   → 인게임 → 결과·리매치 투표 → (로비 복귀 또는 즉시 재시작)
```

### 13.2 보이스챗 정책

- 인게임 근접 VoIP가 유일한 시야 생성원. 디스코드 등 외부 보이스로 말해도 화면이 밝아지지 않으므로 구조적으로 무력화됨("디스코드 금지" 안내 불필요)
- 메아리(탈락자)는 별도 사망자 채널에서만 대화 가능

### 13.3 난입 · 이탈 처리

| 상황 | 처리 |
|---|---|
| 진행 중 난입 | 관전 합류만 허용(다음 라운드부터 참가 가능) |

| 밸브 회전 중 이탈 | 6.4절 참조(진행도 리셋, 밸브 즉시 재개방 가능) |

| 호스트 이탈 | 세션 종료. 호스트 마이그레이션은 v1.x 스코프(MVP 미포함) |

## 14. 네트워크 아키텍처 & 이벤트 프로토콜

### 14.1 스택 선정

| 옵션 | 채택 여부 | 사유 |
|---|---|---|
| **FishNet + Steamworks(Facepunch)** | ✅ 채택 | 무료·CCU 무제한·활발한 유지보수·클라이언트 예측 내장. 필요 시 Steam Datagram Relay 경유 |
| Mirror | 차선 | 레퍼런스는 많으나 FishNet 대비 우선순위 낮음 |
| Photon Fusion | ❌ 배제 | 틱 정밀 동기화용 과스펙 + 동접 과금 구조가 1인 유료 게임과 상충 |

### 14.2 동기화 설계 원칙

- **물리 동기화 없음.** 동기화 대상은 ① 플레이어 위치·회전(10~20Hz 보간), ② SoundPulse/PerceivedPulse 이벤트뿐
- 파문 렌더는 각 클라이언트가 로컬 재현하므로 20~80ms 지연은 체감되지 않음
- 밸런스는 위치+이벤트 트래픽만으로 성립하도록 설계되어(5절), 하드 넷코드 요구사항을 구조적으로 회피
- 5.6절 차폐 계산은 서버에서 수행되며, 차폐로 인해 애초에 도달하지 않는 이벤트는 해당 클라이언트로 아예 전송되지 않아 트래픽이 자연히 절감됨

### 14.3 이벤트 프로토콜 상세

| 이벤트 | 발신 | 수신 | 페이로드 | 트리거/빈도 |
|---|---|---|---|---|
| JoinRoom | Client → Server | Server | `{roomCode, playerName}` | 로비 입장 1회 |
| ReadyToggle | Client → Server | Server → All | `{playerId, isReady}` | 유저 액션 시 |
| MutatorVote (v1.x) | Client → Server | Server → All | `{playerId, mutatorId}` | 유저 액션 시 |
| RoleAssigned | Server → All | All | `{playerId, role}` | 라운드 시작 1회 |
| SoundPulse | Client → Server | Server(내부 판정용) | `{sourceId, position, radius, duration, type, timestamp}` | 발화/이동/상호작용마다(4인 평균 초당 2~4개, ~40byte) |
| PerceivedPulse | Server → 해당 리스너만 | 개별 클라이언트 | `{perceivedRadius, perceivedDuration, sourcePos, worldSpaceRingVisible}` | 5.6 판정 통과 시에만 개별 전송 |
| ValveRotateStart/Progress/Opened | Client → Server → All | All | `{valveId, playerId, progress}` | 상호작용 시작/**밸브별 회전시간(A 3.0 / B 2.0 / C 4.0초)**/완료 |
| PlayerTagged | Server → All | All | `{seekerId, targetId, timestamp}` | 태그 판정 시 |
| EchoKnock | Client → Server → All | All | `{echoPlayerId}` — **위치는 서버가 메아리 현재 위치에서 얻는다**(3.2절) | **25초 쿨다운**, 라운드당 5회 |
| ItemUse | Client → Server → All | All | `{playerId, itemId, position}` | 아이템 사용 시 |
| GameEnd | Server → All | All | `{result, awards[]}` | 라운드 종료 시 |
| HostMigration | — | — | — | v1.x 스코프, MVP 제외 |

> SoundPulse가 트래픽의 대부분을 차지하나, 페이로드가 작고(~40byte) 빈도가 낮아(초당 개자릿수) 대역폭 부담은 미미하다. 위치 보간은 별도 스트림(10~20Hz)으로 처리. `PerceivedPulse`는 리스너별 개별 전송이라 원본 `SoundPulse`보다 오히려 트래픽이 분산·절감된다(차폐로 걸러진 리스너는 아예 수신하지 않음).

### 14.4 까다로운 지점 3가지

1. 본인 목소리 파문의 0지연 로컬 렌더 vs 타인에게 도달하는 이벤트 경로의 강도·타이밍 일관성 유지 (5.3절)
2. Steam Voice 원시 PCM 접근 → 진폭 추출 → 거리 감쇠·3D 패닝, 그리고 5.6절 리스너별 차폐 레이캐스트를 매 이벤트마다 감당하는 서버 부하
3. 술래 방향 게이지의 호스트 권위 계산(클라 조작 여지 축소) — 단, 친구 대상 게임이므로 안티치트는 과투자하지 않음

## 16. 아트 디렉션 스펙

### 16.1 스타일 정의

완전한 흑 배경 위에 발광 라인과 파문만으로 그리는 모노크롬 + 포인트 컬러. 텍스처·라이팅·고급 에셋 사용량 0. 파문의 감쇠 곡선과 라인 굵기 리듬이 곧 아트 퀄리티다.

**캐릭터: 무광 순백색 저폴리 3D + 역할별 림라이트** [신설]

| 역할 | 림라이트 | 특이사항 |
|---|---|---|
| 도망자 | 청록 `#7FE7E0` | — |
| 술래 | 적색 `#EF6A4C` | 고함 시 실루엣 하이라이트 |
| 메아리 | 옅은 보라 `#B79CFF`, **반투명** | **생존자에게 렌더링 안 됨.** 본인에게는 약하게 발광(3.2-2 방향 감각) |

### 16.2 컬러 팔레트

| 용도 | 기본 HEX | 색맹 모드 HEX |
|---|---|---|
| 배경 | `#000000` | 변경 없음 |
| 환경 파문 | `#E8E8E8` → 투명 감쇠 | 변경 없음 |
| 도망자(시안) | `#35F0D0` | `#F2E205` (옐로우) |
| 술래(레드) | `#FF3B4D` | `#3357FF` (블루) |
| 상호작용 오브젝트(앰버) | `#FFB84D` | `#C98A2E` (채도 낮춘 톤, 옐로우와 명확히 구분) |

색은 다섯 개면 충분하다. 신규 UI 요소도 이 팔레트 밖으로 나가지 않는다.

> 위 팔레트는 **파문·UI 색**이고, 16.1의 림라이트 HEX는 **캐릭터 실루엣 색**이다.
> 두 계열은 용도가 달라 별도로 관리한다.

### 16.4 잔상 (Afterglow) [신설]

| 항목 | 값 |
|---|---|
| 대상 | **자기 SoundPulse만** (타인 파문 제외) |
| 범위 | **지형 모서리(edge)만** — 면 채움 없음 |
| 표시 금지 | **플레이어 / 오브젝트** |
| 지속 | **12초** |
| 밝기 | **15% → 0% 선형 감쇠** |

**차선책**: 모서리 렌더가 불가능할 경우에만 **8% 밝기 / 8초**.

찰칵이 섬광(7절)도 이 잔상과 연동되어 지형 모서리를 남긴다.

**형태적 구분(색맹 모드와 무관하게 상시 적용)**: 술래가 발생시킨 파문 링은 **이중 테두리**, 도망자/환경음 파문 링은 **단일 테두리**로 그려 색만이 아니라 형태로도 발생원을 구분할 수 있게 한다.

### 16.3 1인 제작 전략

- 지오메트리는 ProBuilder 블록아웃 수준으로 충분(플레이어에게는 라인만 보임)
- 소품은 실루엣 판독성 기준 20종 이내로 제한
- 파문 셰이더 1개를 전 오브젝트가 공유 — 아트 파이프라인 자체를 셰이더 하나로 수렴

## 19. 접근성 설계

이 게임의 핵심 입력(발화)은 구조적으로 청각장애인에게는 문제가 없다 — 모든 파문이 시각화되기 때문이다. 다만 발화 자체가 어려운 사용자(언어장애, 소음 환경, 심리적 부담)에게는 진입 장벽이 된다. 아래를 확정 대응으로 명시한다.

| 대상 | 대응 | 스코프 |
|---|---|---|
| 마이크 미보유/사용 곤란 | 찰칵이(7절) + 솔로 연습장(12.2)으로 최소 참여 경로 제공 | MVP |
| 발화 자체가 어려운 사용자 | **텍스트 파문**: 채팅창에 문구 입력 시 "속삭임" 등급과 동일한 SoundPulse가 자신의 위치에서 발생. 등급을 속삭임으로 고정해 밸런스 훼손 방지 | v1.x |
| 색각 이상 | 16.2 색맹 모드 팔레트 + 파문 링 형태 구분 | MVP |
| 청각 정보 의존 접근성 보강 | 12.4 파문 자막 옵션("속삭임/대화/고함" 텍스트 라벨) | MVP |
| 실생활 인터럽트 | 5.8 강제 마이크 뮤트 키, PTT 전환 옵션 | MVP |

## 부록 A. 수치 레퍼런스 총정리

**모든 수치는 4인(술래 1 + 도망자 3) 기준.** 본문과 불일치가 생기면 본문이 우선한다.

```
[이동속도]
  도망자 기본        5.0 m/s
  도망자 질주        7.5 m/s
  도망자 질주 스태미나 5초 (소진 시 3초간 -20%)
  술래 추격          5.0 × (1.05~1.12) m/s  (인원별) → 4인 5.4 m/s
  술래 잠행          3.5 m/s (발소리 걷기급 2m)
  메아리             6.0 m/s (콜라이더 없음)

[캐릭터/카메라]
  FOV                기본 90°, 조절 범위 75°~100°
  캐릭터 콜라이더 반경 0.35m (태그 판정 1.2m와 별개)
  시점                1인칭 확정, 크라우치 MVP 미포함
  캐릭터 아트         무광 순백색 저폴리 + 역할별 림라이트
                     도망자 #7FE7E0 / 술래 #EF6A4C / 메아리 #B79CFF(반투명)

[소리 등급 — 발생 반경 / 지속 / 술래 청취 반경(×1.2)]
  Whisper     속삭임  4m  / 0.6s / 4.8m    (RMS -50~-30 dBFS, 방향 표시 없음)
  Conversation 대화   9m  / 1.2s / 10.8m   (RMS -30~-15 dBFS, 방향 표시 10.8m)
  Shout       고함    22m / 2.5s / 26.4m   (RMS -15 dBFS↑, 방향 표시 26.4m)
  Footstep    걷기    2m  / 0.4s / 2.4m    (2m 이동마다 발생)
  Sprint      질주    6m  / 0.8s / 7.2m    (6m 이동마다 발생)
  Valve       밸브    12m / 회전시간 / 14.4m
  Scream      비명    9m  / 1.0s / 10.8m   (술래 외침 22m 안, 억제 실패)
  Knock       노크    9m  / 1.2s / 10.8m   (메아리 능력)
  Breath      호흡음  3m→9m / 0.6s / 3.6→10.8m  (20초 정지 감지)

  ※ Shout(고함, 플레이어 의도)과 Scream(비명, 강제 발생)은 별개 SoundType
  ※ 발생 간격(2m/6m)에는 재질 배율을 적용하지 않는다

[방향 표시 반경]
  청취 반경과 동일 — 대화·비명·노크 10.8m / 고함 26.4m
  불변 조건: 방향 표시 반경 ≤ 청취 반경

[사운드 차폐]
  일반 벽 통과당 반경 배율   ×0.5 (중첩 가능)
  커튼(HardBlocker)         완전 차단(이벤트 미전송)
  지속시간 최소 유지 배율    ×0.5 (그 이하로는 안 깎임)
  계산식: 청취 반경 = 발생 반경 × 재질 배율 × 역할 청취 배율 × (0.5 ^ 벽 통과 수)

[역할별 인지 배율]
  술래  반경 ×1.2, 지속 ×1.5 (서버 판정 단계에 적용되는 기능적 수치)
  도망자  ×1.0
  메아리  거리·차폐 무시 (소나 — 3.2-1)

[재질 배율]  ※ 발생 반경에만 적용
  금속 그레이팅 ×1.5   (직원 통로, 계단)
  타일         ×1.3   (샤워장, 풀사이드, 유아풀, 세탁실)
  콘크리트     ×1.0   (기계실, 약품창고, 물탱크실)
  목재         ×1.0   (사우나)
  나무 마루    ×1.2   (폐극장 지하, 강제 발생)
  매트/카펫    ×0.7   (라커룸, 로비, 관람석, 라이프가드실)
  물(수면 아래) 파문 미발생

[숨 게이지]  ※ 잠수와 비명 억제가 공유하는 단일 자원
  총량        8초
  소모        잠수 -1/초, 비명 억제 -3 (1회성)
  회복        마지막 소모 후 2초 대기 → 수면 +2/초, 물 밖 +4/초
              (기존 "물 밖 즉시 100% 회복"은 삭제됨)
  질식 페널티  강제 부상 + 이동 -20% 3초 + 고함급(22m) 파문 1회

[술래 외침]
  선딜 1초 정지(이동 시 취소) / 쿨다운 45초
  공포 반경 22m (능력 판정 — 차폐 미적용)
  자동 비명 Scream 9m·1.0초 → 술래 청취 10.8m
  억제: 선딜 1초 내 숨 참기, 게이지 3초 소모

[정지 감지 — 캠핑 방지]
  20초간 누적 이동 3m 미만 → 호흡음 3m/0.6초
  15초마다 +2m, 최대 9m, 5m 이상 이동 시 초기화
  적용: 도망자 + 술래 (메아리 제외)
  미발동: 밸브 중 / 잠수 중 / 메뉴 중 / 이동 불가 연출 중 (타이머 정지)

[메아리]
  이동 6.0 m/s, 태그 직후 3초 암전 + 조작 불가
  소나: 맵 전체 파문 관측, 잔류 3초 감쇠, 동시 표시 최근 8개(테스트 6~12)
  가시성: 생존자에게 렌더링 안 됨 / 메아리끼리는 보임
  노크: 발생 9m·1.2초, 쿨다운 25초, 라운드당 5회, 전환 후 20초 잠금
        발생 위치 = 메아리 현재 위치 (지점 지정 없음)

[태그 판정]
  접촉 반경   1.2m, 1회 접촉 즉시 확정
  태그 2명 도달 시 즉시 술래 승리 확정

[맵 — 심야 실내수영장]
  크기 52×40m (L자형), 2층(관람층 Y+3.5m), 13구역, 대각선 약 65.6m
  밸브 A 기계실 3.0초 / B 메인 풀 수중 3.5m 2.0초 / C 물탱크실(2층) 4.0초
  밸브 간 거리 A↔B 34m / B↔C 32m / A↔C 44m
  순환로 L1 96m / L2 44m / L3 52m / L4 20m
  출구 2개 — 배수로(남동, 금속 ×1.5) / 정문(북서, 카펫 ×0.7), 직선 약 52m

[밸브/시간 — 인원별, MVP는 4인만 구현]
  2인: 밸브2 · 이속+5%  · 6분   (v1.x, AI 술래 필요)
  3인: 밸브2 · 이속+6%  · 8분   (v1.x)
  4인: 밸브3 · 이속+8%  · 10분  (✅ MVP — 정식 밸런스 기준)
  5인: 밸브3 · 이속+10% · 10분  (v1.x, 승리 목표 인원 재계산 필요)
  6인: 밸브3(회전+25%) · 이속+12% · 12분  (v1.x, 승리 목표 인원 재계산 필요)

[승리 판정]
  밸브 3개 개방 AND 탈출 > (태그 + 미탈출) → 도망자 승리, 그 외 술래 승리
  우선순위: 탈출 → 태그 → 시간 종료 → 승리 판정
  UI는 "먼저 2점" 표현이나 내부 점수 변수는 만들지 않는다

[아이템]
  찰칵이  1회용 소모품, 동시 소지 1개, 반경 6m, 0.3초 순간 섬광,
          소리 없음(파문 이벤트 없음), 리스폰 120초, 맵당 4곳
          ※ 시야가 닿는 6m 안의 플레이어에게는 빛이 보인다

[잔상 Afterglow]
  자기 파문만 / 지형 모서리만 / 12초 / 15%→0% 선형
  차선책: 8% 밝기 · 8초

[음성 입력]
  기본 방식        VAD(오픈마이크), PTT는 설정에서 대체 가능
  대역 필터        80Hz~3,400Hz
  연속성 최소 프레임 3프레임(60ms)
  디바운스         0.15초 미만 무시

[소음량 vs 노출 면적]  ※ 통일하지 않는다 (5.0-1)
  소음량      발생 반경 × 지속시간  (선형) — 어워드 채점(8.2), 캠핑 누적 비교(3.6)
  노출 면적   발생 반경² × 지속시간 (제곱) — 소리 등급 격차의 설계 근거(9.1)
```

## 부록 B. 용어집 (Glossary)

| 용어 | 영문 | 정의 |
|---|---|---|
| 파문 | SoundPulse | 소리 발생 시 생성되는 시야 이벤트. 위치·반경·지속시간·타입 포함 |
| 리스너 | Seeker | 술래 역할, 세션당 1인(v1.x 대형맵 2인). 외침 능력 보유(3.5) |
| 도망자 | Runner | 밸브를 열고 탈출해야 하는 역할 |
| 메아리 | Echo | 태그당해 탈락한 도망자. 유령 상태로 노크 능력을 통해 계속 참여. **생존자에게 렌더링되지 않으며 소나 시야를 갖는다**(3.2) |
| 밸브 | Valve | 회전시켜 여는 탈출 게이트 트리거 |
| 리매치 | Rematch | 라운드 종료 후 과반 투표로 즉시 역할 재추첨·재시작하는 것 |
| 뮤테이터 | Mutator | 같은 맵의 규칙 문법을 재조합하는 선택적 라운드 변형 |
| 사운드맵 타임랩스 | Soundmap Timelapse | 판 종료 후 해당 판의 모든 파문을 30초로 압축 재생하는 리플레이 기능 |
| 차폐 | Occlusion | 벽·지형지물에 의해 파문의 실제 인지 반경이 감쇠되거나 완전히 차단되는 현상(5.6) |
| 인지 배율 | Perception Multiplier | 리스너의 역할에 따라 동일한 물리적 파문을 다르게 감지하는 배율(5.7) |
