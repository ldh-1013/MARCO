# 마르코! — 프로토타입 전체 구현 프롬프트 (기획서 v0.4 기준)

> **프로토타입의 목적**: "이 게임이 정말 재미있는가? 돈 주고 살 가치가 있는가?"를 확인한다.
> 따라서 **핵심 루프의 모든 고리가 빠짐없이 있어야 한다.** 고리 하나가 없으면 딱 그 지점에서 재미가 끊기고, 그러면 답을 얻을 수 없다.

> **이 문서는 v0.3판을 대체한다.** v0.4에서 밸브 8초 균등·진행도 감쇠·최후 생존자 페이즈가 들어오면서 **블록 구성이 6개에서 7개로 늘었다.** v0.3판 프롬프트는 쓰지 마라 — 수치가 전부 다르다.

---

## 0. 검증해야 할 루프 — 이게 전부 돌아가야 한다

```
말한다 → 음성 3등급 분류 → 파문 발생 → 재질·차폐 적용 → 시야가 밝아진다
   → 잔상이 남는다 → 술래가 방향을 안다 → 추격 → 태그
   → 메아리 전환 → 소나로 관전 → 노크로 유인
   → 밸브를 연다 → 진행도 감쇠와 싸운다 → 역류와 싸운다 → 게이트가 열린다 → 탈출
   → (혼자 남으면) 최후 생존자 페이즈 → 배수구 잠수 → 단독 탈출 = 팀 승리
   → 결과 화면 → 어워드 → "한 판 더"
```

**v0.3 루프와 달라진 곳 두 군데**: 밸브에 "감쇠와 싸운다"가 생겼고, 탈출 경로가 **두 갈래**가 됐다.

## 1. 실행 방식 — 7블록 연속

```
블록 1 (선행 결함 4건 + 맵 v2 + 배수구·수면)
   ↓
블록 2 (밸브 전면: 8초 균등 · 진행도 감쇠 · D·E · 역류 · 무작위 활성 · 게이트 latch)
   ↓
블록 3 (승리조건 3분법 · 인원별 보정 · 종반 압박 · 태그)
   ↓
블록 4 (최후 생존자 페이즈 · 배수구)          ★ v0.4 신설 블록
   ↓
블록 5 (누락된 코어 규칙: 질주 스태미나 · 잠행 · 캠핑 방지)
   ↓
블록 6 (시야 완성: 메아리 소나 · Afterglow · 찰칵이)
   ↓
블록 7 (연출 · 캐릭터 아트 · HUD · 통합 검증 · 빌드)
```

> **왜 블록이 하나 늘었나.** §6.5 최후 생존자 페이즈는 라운드 상태기계에 새 상태를 넣고, 배수구라는 새 상호작용 오브젝트를 만들고, 승리 판정을 3분법으로 바꾼다. 승리조건 블록에 욱여넣으면 그 블록만 다른 블록의 두 배가 되어 검토가 불가능해진다.

## 4. 블록 3 — 승리조건 3분법 · 인원별 보정 · 종반 압박 · 태그

> **승리 판정이 2분법에서 3분법으로 바뀐다.** 그리고 `TagWinThreshold = 2`가 **의미를 잃는다** — 도망자가 1명 남는 것은 술래의 승리가 아니라 §6.5 페이즈의 시작이다.

━━━ 3-A. 승리조건 §6.3 [전면 개정] ━━━
※ 이 코드는 이전에 한 번 고친 적이 있다. 기존 테스트의 의미가 또 바뀐다.

  이전: Evaluate(valvesOpened, totalValves, runnersEscaped, taggedRunners, timeRemaining)
        if (totalValves > 0 && valvesOpened >= totalValves && runnersEscaped >= 2)
        if (taggedRunners >= 2 || timeRemaining <= 0)

        ① 밸브 탈출 승  : gateOpened && runnersEscaped >= EscapeRequirement
        ② 최후 생존자 승 : 마지막 생존자가 배수구로 탈출  (블록 4에서 연결)

★ "살아있는 도망자" = 전체 도망자 − 태그 아웃 − 탈출 완료.

★ 컴파일이 깨지거나 의미가 어긋나는 기존 테스트를 전수 찾아 판단하고 근거를 남겨라.

## 9. 프로토타입이 답해야 할 질문

구현이 끝나면 3~5인으로 플레이하고 기록한다. **이게 프로토타입의 존재 이유다.**

### 1순위 — 이게 안 되면 설계를 다시 본다

| # | 질문 |
|---|---|
| 1 | **"말해야 보인다"는 딜레마가 실제로 긴장을 만드는가** — 말하기를 망설이는 순간이 나오는가 |
| 2 | **술래가 밸브 하나를 계속 지키는 것이 최적해가 아닌가** — 활성 = 요구 + 1의 존재 이유 |
| 3 | **밸브 8초 + 감쇠가 "지금 뺄까, 1초 더 돌릴까"를 만드는가** — v0.4 변경의 핵심 |
| 4 | **최후 생존자 페이즈가 라운드에서 가장 긴장되는 90초인가** — 아니면 그냥 지는 구간인가 |
| 5 | **"한 판 더 하자"가 나오는가** — 최종 기준 |

### 2순위 — 수치 조정으로 해결되는 것

| # | 질문 | 벗어나면 |
|---|---|---|
| 6 | 술래 승률 40~60%인가 | §9.4 순서(①이속 ②회전시간 ③역류)로 조정 |
| 7 | 감쇠 0.10/s가 적절한가 | 너무 관대하면 0.15, 가혹하면 0.07 |
| 8 | 역류 180초가 압박으로 느껴지는가 | 테스트 범위 160~210초 |
| 9 | 배수구 T 공식이 던지기를 실제로 막는가 | 밸브를 일부러 안 여는 플레이가 나오는가 |
| 10 | 60초 이상 무사건 구간이 없는가 | §20.3 합격 기준 |
| 11 | 메아리가 지루하지 않은가 | 소나 8개 상한, 노크 5회 조정 |
| 12 | 무마이크로도 최소한 참여되는가 | 찰칵이 리스폰 120초 조정 |

**1~5번이 "구매할 가치가 있는가"에 직접 답한다.** 나머지는 그 답이 "그렇다"일 때 다듬는 것이다.

## 10. 멈춰야 하는 지점

| 상황 | 조치 |
|---|---|
| 배치 검증(밸브 10쌍 또는 배수구 2개)이 조정해도 합격 안 됨 | **멈추고 보고.** 구역 배치를 다시 계산해야 한다 |
| 기획서 수치와 기존 코드가 충돌 | **멈추고 보고.** 임의로 고르지 마라 |
| 기획서에 정의가 없는 지점 발견 | **GAP으로 기록하고 보고.** 값을 창작하지 마라 |
| ServerPhase 전이 구독처에서 새 상태를 처리 못 하는 곳 발견 | **멈추고 보고.** 과거 사고 지점이다 |
| 탈출자 관전 규칙 | 미정. 프로토타입은 "탈출 = 관전만, 노크 불가"로 임시 처리하고 GAP 유지 |
| 스태미나 회복 규칙 / 페널티 중첩 | 기획서에 없을 가능성이 높다. GAP으로 올리고 임시값 명시 |
| 호흡음의 무성 생존상 집계 여부 | 기획서 미명시. GAP |
| 배수구 T의 실시간 반영 여부 | 기획서 미명시. GAP |
| 거리 판정의 수직 성분 포함 여부 | GAP-71. 한 곳에서만 결정하고 전 계층에 일관 적용 |
| 상호작용 유효 범위 | GAP-73. 밸브·배수구·아이템이 전부 이 값에 의존한다 |

**GAP이 쌓이는 것은 정상이다.** 창작한 값을 확정처럼 적는 것이 사고다.
