# 권위 모델 — 프로토타입 코드와의 차이

| 항목 | 내용 |
|---|---|
| 작성 | 2026-10-05 |
| 기준 | `docs/마르코_상세기획서.md` §14.2 "전체 권위 모델" 표. **규칙의 정본은 기획서다.** |
| 대조 대상 | 프로토타입 코드 `Assets/_Project/Net` · `Core` · `Presentation`(읽기만 했다. 코드는 수정하지 않았다) |
| 용도 | 새 개발에서 프로토타입 코드를 **그대로 가져오면 안 되는 지점**의 목록 |
| 주의 | 이 문서의 "코드 동작"은 규칙이 아니다. 기획서 본문에는 코드 동작을 규칙으로 적지 않는다 |

## 1. 읽는 법

- 번호는 이 문서 안에서만 쓴다. "표 행"은 기획서 §14.2 표의 항목 이름이다.
- 분류
  - **미구현**: 기획서에 있는 규칙이 코드에 없다. 새로 만들어야 한다.
  - **다름**: 코드가 있지만 규칙과 다르게 동작한다. 규칙에 맞게 바꿔서 가져온다.
  - **구멍**: 서버가 확인해야 할 것을 확인하지 않는다.
- 줄 번호는 2026-10-05 기준이다.

## 2. 차이 목록

| # | 표 행 | 기획서 규칙 | 프로토타입 코드 동작 | 분류 |
|---|---|---|---|---|
| 1 | 태그 요청 | 술래가 **좌클릭 시 요청 1회**를 보낸다(§3.1-2). 쿨다운 중이면 보내지 않는다 | 술래가 **사거리 안에 도망자가 있는 동안 자동으로** 요청한다. 같은 대상에게 0.5초마다 재시도한다(`Presentation/Tagging/TagDetector.cs:123-135`). 좌클릭 입력 경로가 없다 | 다름 |
| 2 | 태그 요청 | **서버가 반경 · 각도 안 가장 가까운 1명을 고른다**. 페이로드가 없다 | **술래 클라이언트가 대상을 고른다.** 대상 오브젝트의 RPC를 부른다(`Net/TagNetworkSync.cs:161` `ServerRequestTag`, 호출 측 `TagDetector.cs:135`). 서버는 지정된 대상을 검증만 한다 | 다름 |
| 3 | 태그 판정 · 재검증 | 클라이언트 판정 반경 1.2m, **서버 상한 2.0m**(지연 보정), 방향 ±45°(수평), 대상은 가장 가까운 1명 | 서버 검증 거리가 **1.2m**다(`Core/Tagging/TagRules.cs:27,40` `TagRadiusMeters`). 방향 검사가 없다(`Core/Tagging/ServerTagDriver.cs:32-60`). 지연이 있으면 "분명 맞췄는데 안 잡혔다"가 상시 발생한다 | 다름 |
| 4 | 태그 쿨다운 | 서버가 관리한다. 적중 2.5초 / 헛스윙 1.5초 | 쿨다운이 없다. 서버에는 태그 성립 뒤 **술래 1.0초 경직**만 있다(`TagNetworkSync.cs` `ServerSeekerStunnedAt`) | 미구현 |
| 5 | 목숨 · 첫 적중 · 헛스윙 | 목숨 2.0 / 1.5 / 1.0은 **서버만 보관**하고 본인에게만 보낸다. 첫 적중은 맞은 사람과 술래만 안다(`PlayerTagged` · `HealthChanged` · `TagMissed`). 태그 SyncVar를 켜지 않는다 | **목숨이 없다.** 모든 적중이 곧 메아리 전환이다. `PlayerTagged` · `TagMissed` · `HealthChanged`가 없다. 적중하면 태그 SyncVar가 켜져 **전 피어가 알게 된다**(`TagNetworkSync.cs:221` `_tagged.Value = true`) | 미구현 |
| 6 | 붕대 · 동료 치료 · 신음 | 서버 권위, 이벤트는 본인(붕대) / 치료자와 대상(치료)에게만 | `SoundType`에 `Moan` · `Bandage` · `Treat`가 없다(`Core/SoundPulse/SoundType.cs`는 `Breath`까지). 붕대 오브젝트 · 보유 · 사용 · 치료 코드가 없다 | 미구현 |

| 10 | 메아리 노크 가짜 실루엣 | 도망자 색(청록) 가짜 실루엣을 기본 대기 포즈로 표시 | 없다(9번과 같은 이유) | 미구현 |
| 11 | 탈출 확정 | 서버가 확정한다. 탈출은 **게이트 개방 후 출구 접촉**(§6.3) | 클라이언트 트리거가 요청을 보내면 서버는 **역할 · 게이트 · 중복만** 검증하고 확정한다. **플레이어가 출구 근처에 있는지 위치를 확인하지 않는다**(`Net/RoundNetworkSync.cs:738` `ServerSubmitEscape`, `Core/GameFlow/ServerRoundDriver.cs:72` `TryRegisterEscape`) | 구멍 |

## 3. 문서 쪽 정정 후보(코드가 아니라 기획서 표가 어긋난 곳)

기획서의 규칙끼리 어긋나거나 코드가 더 엄격한 경우다. 이번 작업에서 기획서의 해당 절은 고치지 않았다.

| # | 위치 | 어긋남 |
|---|---|---|
| A | 기획서 §14.3 `EchoKnock` 행 | 수신이 **All**이고 페이로드에 `{echoPlayerId}`가 있다. 노크는 비명 · 신음과 **구분 불가 그룹**(§5.1)이고 발생자 식별이 불가능해야 한다(§3.2-1). 파문은 청취자별로 판정해 보내므로(§14.2) 전원에게 발생자 ID를 보내는 행은 이 규칙과 맞지 않는다. 코드는 청취자별 전달이다 |
| B | 기획서 §14.3 `SoundPulse` 행 | 페이로드에 클라이언트가 `sourceId` · `position` · `radius`를 보내는 것으로 적혀 있다. 코드는 **소리 종류만** 보내고 서버가 신원 · 위치 · 반경을 확정한다(`Net/PulseNetworkSync.cs:337` `ServerSubmitPulse`). 14.2의 "역할 · ID는 호출자에서 읽는다" 원칙과 맞는 쪽은 코드다 |
| C | 기획서 §5.7 청취자 C(Echo) 줄 | "관전 목적, 정보 참고용 동일 적용"(반경 · 지속 ×1.0, 5.6 차폐 적용처럼 읽힌다). 같은 절 표와 부록 A는 메아리가 **거리 · 차폐 무시**(소나, §3.2-1)다. 코드는 후자다(`Core/SoundPulse/SoundPulseResolver.cs`의 Echo 분기) |

## 4. 코드에만 있는 동작(규칙이 아니다 — 가져올지는 기획 결정)

| # | 코드 동작 | 비고 |
|---|---|---|
| a | 파문 전달에 `Appeared` / `Updated` / `Disappeared` 세 종류가 있다. 지속 시간 중 차폐가 바뀌면 갱신 · 소멸을 통지한다(`Core/SoundPulse/ActivePulseTracker.cs:24-33`) | 기획서 14.3은 `PerceivedPulse` 1종만 적는다. 갱신 · 소멸 규칙이 기획서에 없다 |
| b | 라운드 상태를 SyncVar 여러 개로 전파한다 — 페이즈 · 잔여 시간 · 카운트다운 · 브리핑 · 리매치 투표 · 어워드 · 종반 압박 플래그 · 배수구 진행도 등(`Net/RoundNetworkSync.cs:70-137`) | 기획서 §14.2 표의 "라운드 페이즈 · 잔여 시간 · 탈출 인원 수" 등은 **기획서에 미정의**다. 규칙이 정해지기 전에는 코드 구조를 근거로 쓰지 않는다 |
| c | 준비 상태가 플레이어별 SyncVar다(`Net/ReadyNetworkSync.cs`) | 기획서 14.3 `ReadyToggle`(서버→전체)과 같은 결과다 |

## 5. 코드와 일치를 확인한 행

규칙대로 동작하는 것을 읽어서 확인한 항목이다. 새 개발에서 그대로 가져와도 된다.

| 표 행 | 확인한 코드 |
|---|---|
| 위치 · 회전(클라이언트 권위, 전원 동기화) | `Editor/NetworkPlayerSetupTool.cs` — 플레이어 프리팹의 `NetworkTransform`(위치 · 회전 on, 크기 off) |
| 역할 · 메아리 · 탈출 상태(서버 SyncVar, 전원) | `Net/RoleNetworkSync.cs`(배정 SyncVar 1개), `Net/TagNetworkSync.cs`(태그 · 탈출 SyncVar) |

| 파문 전달의 좌표 비공개 · 8방위 | `Core/SoundPulse/SoundPulseResolver.cs` — `wallCount == 0`일 때만 `sourcePos` 공개, 차폐 시 `direction`만 |

## 6. 대조하지 못한 행

코드에서 해당 동작을 찾지 못했거나 기획서에 규칙이 없어 대조할 수 없었다.

- 근접 음성 · 메아리 음성 · 탈출자 음성 · 탈출자 관전: 코드에 음성 오디오 전송과 관전 카메라 경로가 보이지 않는다(`Presentation/Voice`는 마이크 캡처 · 분류까지). 기획서 쪽도 권위가 미정의다.
- 호흡음(캠핑 정지 감지), 질주 스태미나, 종반 압박의 효과별 권위: 기획서에 미정의라 대조 대상이 없다.
